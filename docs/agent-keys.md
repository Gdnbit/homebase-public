# Agent 凭据接入设计

此文档面向接入新工具的开发者。它描述凭据引用如何进入受控进程。保存、轮换、到期和恢复的现行行为见 [密钥生命周期](secret-lifecycle.md)。

## 数据流

1. 用户通过密钥管理界面注册凭据与元数据。目录只向需要的调用者提供已填、过期等状态。
2. 消费者使用服务名与凭据引用。后端按当前来源、有效期和授权解析，失败时提供可处理的原因。
3. 对于需要启动的外部工具，适配器在执行边界把凭据交给目标进程，或使用工具自带的受控凭据接口。
4. 任务回执只记录必要的状态与标识。密钥正文不进入命令参数、诊断日志、已保存对话或发布文档。

不同 Agent 的配置能力不同。可用接入方式包括后端解析、CLI 提供的凭据钩子、显式环境注入和用户已有凭据的受限引用。每个适配器声明读取范围和失效语义。 [凭据引用](service-credential-references.md) · [新增服务接入手册](secret-integration-playbook.md)

## 轮换与核对

已配置表示引用存在。服务可用性要通过用户明确发起的适配器检查或服务商界面确认。轮换分别记录候选验证、切换和旧凭据停用；遇到回执未知时核对原版本，避免重复覆盖。已运行的外部进程可能需要重新启动才能读取更新后的引用。

排查先看执行器是否就绪、引用是否存在、授权和到期策略是否允许，再查服务商返回。展示结果使用服务类别、检查阶段和可执行的下一步。附带记录应使用合成凭据或脱敏状态。

## 开发验收

模拟缺失、空值、已填、期限错误、轮换失败、回退和并发编辑。写入类测试在独立临时目录执行，预览、截图和文档使用假值。本机生产凭据状态留给用户在自己的环境中核对。

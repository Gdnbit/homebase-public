# HomeBase Agent OS 控制面设计

这份设计记录说明 HomeBase 怎样把多个入口接到同一套能力契约、任务回执和授权规则。现行接口以 [生成的命令契约](../control/reference.md) 为准。

## 分层与数据流

| 层 | 负责什么 |
| --- | --- |
| 人机入口 | 桌面、已绑定的微信和本机 CLI 发起对话或业务请求，显示阶段和结果 |
| 助理和工作流 | 组装有界会话上下文、检索可用能力、生成步骤并请求授权 |
| 控制与治理 | 校验参数、来源、授权和请求编号，分配任务回执，提供状态和审计查询 |
| 执行适配 | 连接本机工具、原生 Agent、MCP、Skill、模型服务和通过验收的仓库能力 |
| 本地状态 | 维护任务、产物、缓存和加密配置。读操作使用需要的最小范围 |

模型可以提出行动。宿主决定该动作能否执行，将工具输出作为待核对数据，并保存实际结果。用户可用命令查看 schema、授权、完成规则和错误说明。 [CLI 操作手册](../control/OPERATIONS.md)

## 目录与能力

能力目录按用户要完成的事分组。每项实现分别记录来源、输入输出、依赖条件、成本信息的出处以及账号或本机可用性。通用注册规范描述类别和接口，具体安装内容、启用状态和调用权限由目标机器查询。仓库源码、配置模板和个人生产数据使用独立的存储位置。 [统一能力发现](capability-discovery.md)

Agent 会话、MCP 协议连接和 Skill 工作说明有不同生命周期。Agent 会话按来源管理，MCP 在授权后运行已登记的工具，Skill 的说明在任务需要时加载。凭据在本机受控的后端解析，工具按动作取得所需引用。 [本机工具与授权](assistant-local-tools.md)

## 任务与恢复

每次提交带稳定的请求编号。外层控制任务表示请求受理及执行结果，业务任务记录具体产物或服务商状态。人机入口按原编号复查。接收结果未知时优先核对既有回执；只有确认可以重新执行时，才创建新动作。

状态读取应区分未配置、空结果、读取失败和未知。界面展示真实进展节点，轮询只跟踪仍在运行的原任务。重启后用已持久保存的步骤和产物校验恢复查询。 [会话上下文与恢复](assistant-context-and-recovery.md) · [任务身份](assistant-job-identity.md)

## 治理、迁移和文档

审计记录谁通过哪个入口提出了什么类别的变更、针对什么资源、是否成功。快照恢复先核对版本和范围，再按原入口明确执行。迁移优先导出可移植配置模板；凭据、缓存、插件依赖及模型权重按目标机重新准备。现行审计和快照入口见 [契约](../control/reference.md)，扩展方向见 [设计与成熟度](agent-os-final-design.md)。

# HomeBase Agent OS 设计与成熟度

该文档整理早期总体设计的目标，并将验收分成可逐步验证的层次。 [控制面设计](agent-os-control-plane-design.md) · [现行架构](architecture.md)

## 产品定位

桌面助理是主要交办入口，微信可以用自然语言继续工作，CLI 供本机程序与其他 Agent 使用。会话中心便于查找不同来源的对话，工作台提供状态与运行信息，能力库让用户按用途找出可用实现。

能力库的公开设计重点是通用分组、输入输出、授权、登记和调用。安装或启用清单由使用者自行维护。确认界面展示本次要执行的具体动作、覆盖范围和结果。

## 成熟度分层

| 层次 | 验收条件 |
| --- | --- |
| P0 治理底座 | 配置变更可追溯；已覆盖资源可查看快照；失败保留原输入或恢复依据 |
| P1 环境与迁移 | 能区分硬件探测失败、依赖缺失和模型尚未验证；目标机器可重新绑定资源并检查 |
| P2 Agent 与能力 | 桌面、微信、CLI 共用命令与任务身份；能力目录按功能展示授权、就绪状态和调用条件 |
| P3 长任务与恢复 | 计划、进度、确认和产物分别可查询；重复消息或重启沿用原回执 |
| P4 可扩展验证 | 新实现可独立声明依赖、版本、输入输出、许可证和验收方式 |

前三层可以从治理、环境预检和能力目录查看现行入口。P3 的具体行为以助理工作流、会话恢复和现行测试为准。P4 描述持续扩展的目标。 [维护与路线图](ROADMAP.md)

## 数据和界面边界

- 项目源码保存可复用的契约、界面和合成测试。运行时配置、密钥、用户素材和输出由用户环境持有。
- 项目、会话、任务编号与产物分开登记。只读查看与重新执行分别通过明确入口。
- 大对象和历史正文按需读取；摘要和元数据用于快速发现。界面把未知、失败、处理中和已完成分别表示。
- 工具能力先看入口、权限和依赖，再检验输出。整机权限、迁移和跨渠道一致性按场景分别验收。

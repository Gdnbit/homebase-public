# Agent OS 治理底座实施与验收

这份文档保留早期 P0 的技术方案，适合用于扩展审批、审计、快照和恢复。生产字段通过 [CLI 契约](../control/reference.md) 核对。

## 先覆盖受管的配置变更

从已有适配器经过的操作开始，例如能力设置、连接配置和用户明确发起的配置变更。每种资源声明由谁持有、允许的读写入口和恢复范围。遇到外部程序直接写入时先重新核对现状，避免依据旧快照覆盖有效变更。 [现行治理命令](../src-tauri/src/commands/governance.rs)

## 审计与快照

可公开的审计示例只需要角色类别、动作、资源种类、请求编号、时间、结果和差异摘要。错误文本应能定位步骤。凭据、真实路径、聊天内容和业务载荷保持在实现所需的专用状态中。

1. 写前查看原资源版本，记录能够用于核对的摘要。
2. 执行后回读本次结果，保存审计状态与可用的快照引用。
3. 失败后区分明确未发生、结果未知和已部分发生，继续查询原请求。
4. 需要恢复时先展示范围并校验保全数据，受影响资源通过专用入口恢复。
5. 只读审计、快照查看和回滚分别走各自的授权与确认流程。

用户界面和内部调用可以共享审计写入逻辑。导出或展示只使用明确需要的元数据。 [密钥事务与恢复](secret-lifecycle.md) · [会话档案备份](assistant-archive-backup.md)

## 隔离验收

| 场景 | 应取得的证据 |
| --- | --- |
| 正常变更 | 相同请求能查到唯一结果，审计指向原动作 |
| 并发编辑 | 过期版本被拒绝，原输入保留供人工核对 |
| 持久化中断 | 再次打开能判明已提交、可恢复或待核对 |
| 恢复 | 选定的资源恢复，其他数据与原回执仍可查询 |
| 公开输出 | 测试、日志和文档只含合成数据 |

后续按资源逐项扩展适配范围，核对变更来源与真实 I/O。 [隔离验证地图](verification-map.md)

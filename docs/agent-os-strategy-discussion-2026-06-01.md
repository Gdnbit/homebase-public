# Agent OS 选型取舍

这份文档整理早期的设计讨论。当前产品入口、接口和限制详见 [助理任务工作流](assistant-task-workflow.md) 和 [控制面设计](agent-os-control-plane-design.md)。

## 从用户意图组织能力

先确定用户想完成的事，再按私有数据范围、成本、耗时、账号权限和可用性选择实现。桌面和微信可以复用同一能力；CLI 返回可核对的任务与结果。选用其他 Agent 时按来源保留会话和原生工具的操作方式。

MCP 用于调用明确声明的工具或读取资源。Skill 说明如何按既有流程办事，在需要时提供约束、检查方式和工作方法。模型 API 提供具体推理或生成能力。项目适配器可以封装经过验收的单一功能。目录把这些实现归到相同的用户用途下面。 [能力发现接口](capability-discovery.md)

## 版本、迁移与可观察性

- Git 管理源代码、命令契约和合成测试的版本。依赖固定到能核对的发布包或提交。
- 工作区配置采用可检查的版本字段和显式资源引用。迁移先在目标机检查工具、目录和权限。
- 审计用于回答动作的发起来源和真实结果。快照用于恢复受管数据，保留原版本和恢复依据。
- 状态区分已发现、已配置、已验证、失败、未知。接口诊断尽可能读取原回执，减少重复扫描和重跑。
- 网络诊断描述可复现的请求边界和失败原因。文档采用少量操作入口和任务相关的补充说明，长上下文按需读取。

## 持续完善的顺序

先把能够执行且能核对结果的主链路做完整，再扩展迁移、恢复和高级工作流。每个扩展先写输入、输出、失败态和最小合成验收；按问题复现记录和影响范围安排迭代。 [项目路线图](ROADMAP.md) · [维护迭代](maintenance-goal.md)

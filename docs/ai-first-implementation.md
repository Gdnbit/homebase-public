# HomeBase 助理主入口与统一工作环境

本页说明助理主入口、统一会话和能力库的设计。当前运行时请参考 [助理说明](assistant.md)。

## 首期落地与事实源

- `/` 为 AI 助理，`/assistant` 旧链接继续有效。`/conversations` 聚合 HomeBase、微信与原生 Agent 历史；`/workbench` 展示助理任务/服务商上报用量及原系统概览。旧 `/dashboard` 转到工作台。
- `/capabilities` 默认按功能组织已有实现；原模型目录、开源项目注册表、MCP 池、Skill 池仍是各自唯一配置源。索引只有派生元数据，不保存凭据值。工具与工作流的配置入口收进能力库，Agent 管理继续负责 Agent 本身。
- 资料库、密钥与连接独立保留。文章、投料、快捷面板、旧历史时间线、操作记录与系统页的原路由/内容保留，可从设置访问；不删除数据，不宣称所有旧工作流已变成助理自动化。
- 高级集成中保留外部 AI 启动说明与 CLI/MCP 接入。HomeBase 内发起的对话不要求用户手动复制提示词。

## 自动上下文

`assistant_context_get(sessionId?,query?)` 生成 `homebase-context-v1`：当前会话、状态版本、授权版本、相关记忆、有限原任务/产物引用、工作区授权摘要、能力与接口发现方式。该查询不会恢复、取消或修改任务，也不读取凭据正文。

每次 `assistant_send` 自动组织相同上下文，桌面与模拟/真实微信共用同一个 Engine。正文资料、记忆、历史结果不是指令或授权。结构修订2新增9000序列化字节上限、总数/省略标记、真实进度/最新要求及原运行时能力：最多4条相关当前记忆、6个非聊天任务，优先进行中、排队FIFO、最近结束。完整历史和检查点不裁剪；完整进展仍按原任务查询。工具schema按需发现，权限由原执行器核对。指纹只反映可见事实及query，不因无关会话或读取时间变化；[完整契约与恢复边界](assistant-context-and-recovery.md)。

`capability_index_query`是当前按需发现入口：按功能/来源/关键词筛选，返回有界分页、固定catalog_id/snapshot_id和真实next_offset；显式刷新才生成新目录，过期明确重查。旧`capability_index_get`保留兼容。参见[能力发现契约](capability-discovery.md)。模型已收录、MCP已授权或Skill有说明不等于真正调用成功。来源失败、说明省略和未知费用均显式提示；选择实现只准备助理草稿，发送后才执行。自动选择仍受免费模式、凭据绑定与已有授权限制，不允许未知费用当作免费或悄悄切换付费渠道。

`assistant_history_query/read`提供固定快照的历史关键词分页和完整JSON分块；原完整会话接口保留。内置运行时8通过`homebase_history`只读当前会话及截止轮次，旧运行时工具集不扩权；历史是资料，不是新的执行授权。范围、过期、偏移与容量错误明确返回，按SHA校验完整正文，参见[历史读取契约](assistant-history.md)。这是热历史读取消费者，冷归档和桌面“加载更早”仍未完成；本阶段原生验收进度见报告。

## 原生会话

桌面聊天现在用[有界会话窗口](assistant-session-window.md)：每次最多40条/256KiB、正文完整，旧步骤按展开读取；真实更早分页、原锚点刷新和独立的最多6条交接读取已接通。原完整会话接口及固定历史分块仍保留。具体原生与UI证据见窗口验收，不把窗口当作完整检查点或冷归档。

原任务读取、发现元数据与自有结果的区别，以及身份冲突/迟到查询的处理见[任务身份和结果归属](assistant-job-identity.md)。视频、仓库与Skill引用不能因为字符串相同就互换；查询错误不会授权重新执行。

`conversation_providers` 查询当前适配范围。HomeBase/微信共用原执行器；Codex 使用[官方 App Server](https://developers.openai.com/codex/app-server) 的 stdio JSONL，不是调用同名模型 API。后续已补齐 Claude Code/Gemini 的原生新建、发送与续接，当前说明见[原生 Agent](native-agents.md)；旧版 Gemini 提示日志仍只读，没有适配器的来源继续明确只读。本页末尾版本和测试计数是首期历史快照，不替代后续验收。

`conversation_native(request)` 的 `action`：

| action | 参数 | 行为与验收 |
| --- | --- | --- |
| list | cursor? | 分页原生会话元数据，不调用模型 |
| read | thread_id | 原会话内容，不 resume、不推理 |
| status | thread_id | 当前连接的事件投影；未载入明确返回 not_loaded，不自动开进程 |
| create | request_id | 新建独立会话工作区，返回真实 thread.id；尚未推理 |
| send | thread_id,text,request_id | 显式续接原生会话并发送；accepted 只是受理，继续 status |
| interrupt | thread_id,request_id | 仅请求停止已知原生在途任务，实际终态仍查询 |

此复合入口在 CLI 上统一要求 write/private/external，不能因为 action 名称改成免授权通道。内置助理禁止调用 conversation_*，避免模型创建另一代理绕过权限。桌面不把读历史当作已续接。

新建 Codex 会话真实注册 `homebase` 动态工具，提供 context/discover/describe/task/status。执行通过 task 委托已绑定的 HomeBase 会话；共享执行器仍负责文件、终端、模型、仓库、MCP、Skill、确认、任务与产物。原生文件访问只读，禁止提权与自行读取秘密。需要本人确认时打开关联的助理会话，不能由模型自批。

已有 Codex 会话保留其原工具绑定；不能假装通过提示词就新增工具，可交接到新建会话。原生账号/模型沿用 Codex，其订阅及模型费用不受 HomeBase 免费路由保证。未改写 Codex 全局配置或登录信息。

写入前先加密保存稳定 request_id 回执。超时/断线结果未知时不重发；重复编号返回原回执，不同内容冲突拒绝。原生 thread.id 与共享执行器 session.id 在加密回执中绑定；动态工具不能选择其他会话的任务。连接断开标为 unknown，应用退出停止自己拥有的原生子进程。

Codex 新建空会话的首条消息直接发送给当前进程持有的 thread，不错误地恢复尚未落盘的历史。已有持久会话显式 resume。未发送的新空会话不承诺跨应用重启续接；不同 Codex 版本的历史是否能继续，仍以原生协议实际返回为准。历史分页每次 20 个轮次；实时投影最多 128 个条目并按事件顺序展示，不每次传输全量历史。桌面切换页面保留内存中的原生草稿、未决请求和所选会话；不会自动发送。

切换 Agent 使用显式交接：保留原会话/原任务；选择最近最多 8 条有限摘录和新目标，准备可编辑草稿，发送前不执行、不取消旧任务。摘录不是模型生成摘要，不宣称有无损跨 Agent 原生状态迁移。

## 用量

`assistant_usage_get` 只汇总已保存的服务商上报记录。无记录返回 null；部分统计注明缺项和未上报轮次。费用单位 USD，不推算原生 Agent 订阅成本、不把未知值补零；工作台不构成完整账单。

工作台可见时，同批助理任务变化只刷新一次用量。页面离开后，变化只标记缓存过期，下次进入再读。若读取期间又有变化，当前读取结束后合并补查。用户也可以点「刷新用量」。读取失败时收起旧合计并显示错误，重试成功后恢复展示。

工作台明细按服务商上报的模型名汇总现有记录。同名记录合计，按记录数列出最多 12 个模型，另外显示「模型未上报」及其余模型合计。每行分别给出已取得的输入 Token、输出 Token、美元费用和缺失数量。费用为空时显示未知，极小的非零金额保留有效数字。现有加密会话和冷归档摘要原样可读。CLI 的 `assistant_usage_get` 有同一组明细和完整返回 schema。 [OpenRouter 用量报告](https://openrouter.ai/blog/announcements/smarter-charts-inline-svgs-and-live-usage-accounting/) · [DeepSeek 请求用量字段](https://api-docs.deepseek.com/api/create-chat-completion/)

模型明细在五项核心测试中覆盖冷热记录对账、未知项和未上报轮次，查询期间没有读取归档正文。21 项浏览器、35 项接口契约、类型、相关 lint 和前端构建通过。独立 Windows 测试程序用同一份合成加密资料对照实际界面与签名 CLI，两端读到相同模型行及未知金额，窗口退出为 0，原合成加密资料摘要一致。日常 v101 保留，正式分发包未更新。真实状态、凭据密文、账本和快捷方式摘要一致，真实模型和微信测试消息为零。 核心对账 · 浏览器 · Windows 与 CLI · 数据保全

隔离对照中，旧版工作台未自动反映从 12 到 34 的合成 Token 变化。修复后 20 项浏览器、4 项既有核心用量及归档验证、35 项接口契约通过，TypeScript、相关 ESLint 和生产前端构建通过。日常 v101 保留，改动尚未打包。 修改前复现 · 浏览器验收 · 核心验证 · 数据保全

## 验证边界


原生协议通过不等于生产账号可用；真实微信投递与真实厂商推理不在无密钥隔离测试中冒充完成。

## 本轮验证与差异

- `npm run build`、受影响前端文件的 ESLint、原生 Cargo check/build、`control:check` 通过；未增加依赖或升级执行框架。
- `test:control`：首次全套后端 177 通过、7 项显式集成测试按条件跳过，控制 CLI 集成 20 通过；接口契约与结果判定 11 通过。新增原生事件顺序/去重/有界投影检查另执行 2 项通过。
- Edge 页面回归 30 项通过：助理首页、统一会话、交接草稿、原生未知受理后离开/返回、功能选择、旧模型/仓库流程、缓存、任务完成更新、确认、提醒、要求修改和 1024/1440 宽度检查。截图为实际 React 页面和合成数据，不是设计图，也不是生产数据截图。
- 本机真实 Codex 程序连接回环合成模型，通过真实 HomeBase CLI 完成新建、动态上下文工具、委托共享执行器、查询原任务、原生终态、读取历史与重启去重；4 次合成模型调用，真实 Key 使用和真实微信测试消息均为 0。隔离默认模型仍停用，委托任务如实返回 disabled，没有假称执行成功。
- 单独运行真实 Deep Agents 图、真实无 Key Marked CLI 与模拟微信的端到端：实际执行 1 次，重复消息未重做，状态/结果查询与加密附件发送通过，桌面与微信产物 SHA 一致，重启保留原结果。没有发送真实微信消息。
- 仓库每页 20 条，模型每页 200 条。来源错误单独提示，缺失目录要明确报告。

本期复用对话内的任务计划、证据、确认和结果卡片。文章、投料与快捷面板的原工作入口已收进设置，原内容未删除；它们全部变成自然语言工作流、更多原生 Agent 适配和更细的能力选择策略仍是后续阶段，不能由首期导航整合推断为已实现。

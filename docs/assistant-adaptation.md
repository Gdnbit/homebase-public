# 私人助理：纠错、事件跟进与在途修改

微信普通消息与桌面自动交流使用同一个引擎。原任务、长期偏好与后续事项分别记录，当前要求优先于旧偏好；不会把“这次换个颜色”自动保存为长期偏好。

## 纠正已有记忆

先通过 `assistant_memory_search({query})` 或模型工具 `homebase_memory(search)` 查找原记录，得到 `revision`、原 `id`、`expected_sha256`。

查询默认 offset=0，按工具结果字节预算分页；has_more=true 时沿用 query 和 next_offset 继续，revision 变化则重新查询。只发送相关当前正文与纠错指纹，不重复加载 previous/corrections 历史。单条内容因大量转义字符等超出预算时明确返回 content_preview/content_truncated，不能当完整原文；完整内容与历史由 `assistant_personal_get` 查看。排序候选仍最多12条，需要查其他内容时使用更具体的标题关键词。

纠错参数示例：

```json
{"request":{"revision":1,"id":"<查询得到的原id>","expected_sha256":"<查询得到的指纹>","content":"动画用蓝色圆点，字幕用简短中文","reason":"用户明确纠正原颜色偏好"}}
```

调用 `assistant_memory_correct`；模型工具对应 `homebase_memory(action="correct", ...)`。模型写入仍等待本人确认；CLI 需要本机已认证的 write/private 授权。必须替换示例中的版本、id 和指纹，不能照抄。

模型共享工具可能同时携带原标题或有效期；纠错时只接受与原记录一致的值，不把这些字段当作重命名或延期指令。创建确认草案前先校验字段、版本和指纹；缺少版本或参数不符时返回结构化错误，让模型重新查询或修正参数，不先弹一个无法执行的确认。本人确认后仍再次校验，防止等待期间内容已改变。

纠错保留原 id、标题与有效期，不创建副本、不恢复到期记忆。当前版本和原内容指纹同时校验；冲突返回 `MEMORY_STALE`，须重新查询并确认。`assistant_personal_get.memories[].corrections` 保留最近10次更正的原因、旧内容、旧来源、新来源与时间；原 `previous` 仍保留最多5次内容/有效期变化。删除记忆同时删除这些历史，原会话与任务检查点仍单独保留。普通编辑、重命名、变更有效期仍使用完整表单 `assistant_memory_save`。

## 指定事件发生后跟进

使用已有 `assistant_followup_save` 或 `homebase_followup(create)`，可选：

```json
{"trigger":{"turn_id":"<本人尚未结束的原任务>","on":"completed"},"notification_policy":"meaningful"}
```

其他必填项与定时办事相同：先 list 获取独立 revision，填写 title、instruction、due_at、max_runs。设置 trigger 后，`due_at` 表示等待截止，`max_runs=1`，不设置重复间隔；仍须本人确认。不能监听其他来源、普通讨论、已发生的目标状态或主动跟进任务。

宿主向模型提供当前 turn_id/session_id；`homebase_task(get)` 也返回当前身份。“这条任务完成后”可直接绑定当前任务，不要求用户查找内部编号。请求已明确、信息齐全时，模型先通过工具准备真正的确认草案，再由宿主展示确认卡；单纯回复“已备好草案，请确认”不等于登记成功。工具执行结果注明该次实际确认状态，不能把一次真实确认扩展为其他操作的授权。

- `completed`：原任务真实完成后，沿用原会话查询既有结果和附件，不重新生成。
- `needs_attention`：原任务等待确认、失败、需要输入、预算暂停或明确中断时，启动独立后续上下文，附原任务真实进度快照；原任务不会被擅自确认或复跑。

内部状态变化负责唤醒，模型不定时询问有没有变化。事件匹配与后续请求身份持久化，重启核对原 request_id/turn_id，不重复创建已受理的任务。状态为 `waiting_event → scheduled → running → completed`；未在截止前观察到事件为 `missed`，未匹配的原任务结束为 `paused`。`event_deadline` 保留原等待截止，`triggered_at` 记录观察到事件的时间，触发后的 due_at 为本次调度时间。只覆盖 HomeBase 已登记任务状态，不是任意网页、邮箱或外部 webhook 监听。应用退出不执行；微信须保持原本人绑定连接；免费渠道、模型/授权版本、容量与额外确认约束沿用原调度器。

## 有意义时再通知

新主动计划默认 `notification_policy="meaningful"`，可明确选择 `all` 每次汇报。旧计划反序列化默认 `all`，不会静默改变已有约定。

只对成功的主动只读检查做跨执行比较。比较实际结构化证据，忽略传输编号、检查时间等噪声；不依赖模型是否使用“没变化”字眼。同一计划重复证据标记微信 delivery=`suppressed`，原结果仍可查询。写入、未知/失败、确认、新附件、没有可比证据的回答以及本人主动查询不参与静默。主动执行的同阶段进度不反复发心跳。

成功的能力发现、接口说明、Skill 读取、工作区列表和计划列表属于准备查询，不作为被检查对象的变化证据；若整次任务只有这些查询，没有实际业务证据，则照常通知。准备查询失败仍明确提示，不能因忽略成功准备查询而隐藏错误。已确认的巡检执行只做本次检查，间隔、次数和通知由宿主管理，不反复登记计划或要求用户再次确认。

筛选凭据与发送声明在同一加密保存中提交，再调用微信发送接口；保存失败不发送。发送结果未知不盲目重发；accepted 仍只代表接口接受。这里只筛选已接入的主动任务结果，不擅自屏蔽个人微信其他消息，不提供离线后台推送或手机已读判断。

## 执行中补充或改变要求

微信或桌面 `auto` 消息可自然说“这个改成两句中文”“别保存旧方案，先只核对”。前台只有路由工具：原消息追加到指定原任务；独立的新事情仍排队，只读讨论不改任务。分类可能判断错误，需确定性控制时使用本机接口：

```json
{"request":{"turn_id":"<assistant_turn_get查询的原任务>","revision":0,"request_id":"<本次补充的固定编号>","text":"改成两句中文，继续原任务，不重新执行已完成步骤"}}
```

调用 `assistant_turn_steer`，原版本来自 `assistant_turn_get.requirements_revision`。同编号同内容重放返回原收件，不重复追加；同编号不同内容或目标拒绝。每任务最多16条、每条8000字节。微信内部只能修改本人来源；本机已认证接口可管理本机显示的微信任务。CLI 需 write/private/external 授权，因为原任务可能继续推理或执行。

收件后保留原 task id、原文、要求版本与时间。正在执行的工具先到安全节点；旧确认失效，尚未执行的旧工具调用返回 `REQUIREMENTS_CHANGED`/`superseded`，不能成为完成证据。新方案需要确认时，微信按新的确认身份发送新卡片，即使中间很短的“处理中”没有被轮询看到，也不会误认为旧卡片已经通知。模型下一轮读取最新要求；若新要求在推理期间到达，旧最终答案不能结束任务。已提交业务动作不假装撤销、不重新提交，旧附件意图清除后须重新核对和安排。原计划已完成的证据保留，可调整未完成阶段。

自然语言分类使用开始判断时所见的原任务要求版本。分类尚未回来时，如果桌面或另一条已受理的操作修改了原任务，迟到的结果无法把较早的要求追加到新版。微信会回复「原任务已有更新，这条补充未应用」。原任务可以继续按最新要求处理，收到补充的那条会话消息仍可查看。

查询原 `assistant_turn_get` 的 requirements 与最新任务结果。收件成功不代表动作已经按新要求完成。已结束/暂停任务、旧运行时或来源不符会明确拒绝；结果未知不自动重新推理。新能力从 `homebase-da-20261113.6` 开始，旧检查点仍使用原工具契约。显式 `mode="task"` 继续表示独立排队任务，`mode="chat"` 保持只读。

开发依据、隔离测试及保全结果见 官方源码对照与验证报告；不能把合成模型通过当作任意真实模型都能正确理解自然语言的保证。

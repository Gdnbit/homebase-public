# 助理会话档案的本机加密备份

HomeBase 可以备份已发布的分段会话档案。备份固定一个索引代次，逐段核对原会话、顺序、编号与校验值。创建成功后返回备份 UUID、索引代次、密文大小、分段计数和本机目录。会话继续写入时，备份仍对应开始时固定的代次。

## 桌面

在「会话」页打开「会话备份」。创建前会记住本次编号。关闭弹窗、切换页面或重新打开程序后，再次进入弹窗会查询最近的原编号。超过 15 秒的等待会提示核对，实际备份可能继续。先用「查询状态」确认结果。未找到时可明确选择用原编号继续创建，后端对同编号只保留一份备份。

已发布的备份可展开「查看文件清单」。清单按页读取，区分已保存、不可用和原件变化。选择「只读查看草稿」时，可核对原版本、已保存正文、旧待核对请求及录音回执数量。关闭弹窗后需要重新打开清单。

「取回原件」会把选中的副本写入该备份目录。草稿副本保留原密文，PDF、录音及任务产物写出原内容，PNG 写出应用导入时核验并去除元数据后的图像。界面显示核验后的本机路径。如果取回超时，对同一项再次操作会先核验已有副本。有不同内容的副本会被保留。

已发布时可以复制本机目录。可以按 UUID 查询旧备份或通过 CLI 创建的备份。另存时会分配新编号，旧编号仍可查询。

## CLI

在 HomeBase 控制 CLI 中创建一个 UUID 作为 `backupId`，保留它以便查询。创建命令 `assistant_archive_backup` 需要私人及写授权。查询命令 `assistant_archive_backup_get` 需要私人授权。两条命令均接受 `{"backupId":"<这次备份的 UUID>"}`。命令描述列出了可复制的调用模板。

| 状态 | 含义 |
| --- | --- |
| `not_found` | 查询时尚未看到这个备份目录 |
| `incomplete` | 已看到目录，密文头尚未发布 |
| `published` | 密文头已发布，返回原代次和目标目录 |

收到受理编号或遇到超时后，先查询原控制任务与原备份 UUID。同一 UUID 只能创建一次。另一次备份意图使用新的 UUID。状态查询校验已发布密文头及其绑定的旧密文，恢复读取还会校验各个分段。

备份由 HomeBase 写到本机助理目录下的 `backups/<UUID>`。其中含 `history-v1`、索引引用到的旧 `state.dpapi`、文件清单和独立加密原件。它保存分段档案中的消息、任务、状态、正式发送的 PDF 引用对应的原件，以及工作区内核验过的自有产物。核验后的桌面草稿、草稿当前或待发送内容引用的合格 PDF 原件、桌面录音原件也纳入备份。模型密钥、现有微信凭据和其他工作区各自按其原存储管理。使用当前 Windows 用户在同一台机器核验副本。

## 查询与解出配套文件

档案发布时，`files.saved` 是保存的文件数，`files.unavailable` 是无法保存的文件数。档案自身的 `encrypted_bytes` 是历史分段及索引的密文字节。文件不存在、与登记摘要不符、超出读取上限或越出工作区时，清单保留逐项状态。较早的备份没有文件清单，仍可原样读取会话档案。

使用 `assistant_archive_backup_files` 查询原 `backupId`。最多 20 项，续页使用返回的 `next_offset`。用已保存项的 `id` 作为 `fileId`，调用 `assistant_archive_backup_file_recover`。后者需要私人和写授权，核验密文解出的字节及 SHA-256，再在原备份的私有 `recovered` 目录下解出明文副本。重复调用会校验并返回同一路径，修改过的副本保留原样。该步骤解出原文件供用户使用，原会话和任务继续由各自存储管理。

## 取回草稿、录音与图片

文件清单中的 `drafts_indexed` 表示备份包含独立草稿清单。`unreadable_drafts` 记录无法确认原编号的草稿数。每份可读草稿按捕获时的原版本保存。较新的编辑正文与旧待发送请求分别保留。录音沿用原录音编号、转写任务编号和已保存的转写，仍存在且摘要一致的音频作为独立文件保存。已清理的音频会标为不可用。

用 `assistant_archive_backup_draft_get` 按实际 `backupId` 和草稿 `fileId` 只读查看内容与回执，需要私人授权。用逐项解出命令取回草稿时，原密文按登记文件名保存在备份下的 `recovered/desktop`，可以在隔离目录复核原版本。音频在私有 `recovered` 目录解出。操作只在备份副本上进行，发送与 ASR 仍按原入口和编号查询。

新备份在独立的加密清单 `image-files.dpapi` 记录当前草稿、待核对发送及已受理桌面轮次引用的 PNG，`images_indexed` 表明可查到这一清单。清单按会话归属持有取回编号，同一会话多次使用同一份准备图片时只保存一次。原图不存在则标记不可用，密文损坏或内容校验冲突标记原件已变化。预览显示当前和原待核对图片的文件名，取回图片时使用 `kind=image` 的 `fileId`，在私有 `recovered` 目录得到摘要一致的 `.png`。解出不会写入活动图片库、发起模型请求或恢复未决发送。

活动 PNG 缺失时，明确取回的副本可用 `assistant_desktop_image_stage` 按草稿原范围和原文件名重新准备。继续前逐项比较返回的 `scope`、`name`、`sha256` 和 `bytes`，确保和原引用一致。若有待核对发送，按原请求查询回执，再决定是否继续，原编号保持不变。

旧备份中的 `images_indexed` 为 `false`，无法从中找回图片。旧版程序可继续读取独立的会话文件及草稿清单。含 PNG 字段的活动草稿需要识别该字段的新版操作。

# 助理上下文与执行中修改

当前契约：`homebase-context-v1`，新增投影结构版本 `projection_schema_revision=2`。旧任务保持原运行时版本，不迁移任务、模型路由或检查点。

## 上下文是只读摘要

`hb describe assistant_context_get` 提供完整输入/返回 Schema。参数 `sessionId` 是原 HomeBase 会话编号；不传时返回空会话工作视图，不选择其他会话。`query` 最多8000 UTF-8字节；仅用于检索有效、未到期的当前记忆。接口不会启动模型、恢复任务、执行文件操作或读取密钥正文。

序列化 JSON（含指纹）最多9000字节；字符转义和中文/emoji都计算在内。它不是完整历史，也不是工具授权：

- `tasks` 最多6个非聊天任务，优先进行中，其次原队列FIFO，最后最近结束的工作；`tasks_total` 包含本会话全部非聊天任务，`discussion_turns` 单列讨论轮次。聊天不会挤走仍在执行的任务。
- 每个任务保留原 `id/state/route_id/runtime_version`、真实进度、最近两次要求及其版本、结果摘要和原产物引用。`runtime_features` 表示已适配的协议能力，不表示当前操作无需确认；旧任务不能因新程序版本而被假称支持新功能。
- 最多4条相关当前记忆；不复制纠错历史或归档内容。`memory_candidates` 是此次检索命中的有效候选数量，不是记忆库总量。
- 授权工作区只提供ID、访问级别和auto_write，路径按需通过原接口获取。共享模型默认值是执行器设置，不是Codex/Claude/Gemini的原生账号。
- 超过字节预算时进一步缩减较低优先级条目和文字。`*_has_more`、`*_truncated` 与 `context_has_more` 明确表示省略；标识不会被截断。极端元数据仍超限时明确失败，不返回损坏JSON或其他会话内容。

完整任务用 `assistant_turn_get` 查询；要求先确认可用接口/schema。产物仍按原任务归属与原结果接口核对，不能据摘要重复执行。原始会话和检查点不因摘要裁剪而删除。

`fingerprint` 是可见事实和query的身份；不包含读取时间`assembled_at`或全局`state_revision`。其他会话发生无关更新不会改变它；当前任务、相关记忆、共享默认值或权限变化仍会改变它。它不是原始JSON全文校验和，也不是执行授权票据。

桌面小面板只有打开才查询。相关事件400ms合并刷新一次；无关会话不读取当前摘要。关闭的摘要只标为过期，重新打开再读取；不启动页面外轮询。

助理执行时，提交阶段只保存会话和任务摘要。首次开始时才按用户正文召回有效的长期记忆，附件或转写正文不参与自动召回。已明确绑定原视频的剪辑请求补充「视频剪辑」主题。文本检索移除「按之前的方式」「照咱们上回那套」等通用短语后，再用剩余任务描述匹配记忆。送给模型的用户原话保持完整。排队期间纠正、删除或到期的偏好不会作为旧版本进入第一次模型请求。旧版已入队但尚未执行的轮次在启动时清除预存记忆副本，再读取当前记录。已开始的轮次保留原检查点，恢复不重新召回。

## 原任务修改与重启恢复

在途修改仅对可继续的 Pi 任务开放，并按原工具协议版本校验。旧的协议编号仍用于读取归档和核对能力契约。

任务恢复后如停在`awaiting_confirmation`，显式修改要求会先持久保存原任务的要求修订，再通知已有worker或唤醒原任务worker。仍使用原任务ID、原路由和原检查点；同一修改编号幂等，不重做已完成的动作。没有启用模型时不自行发起模型调用。读上下文、打开页面、切换页面不会触发此唤醒。

微信和桌面使用同一Engine。前台讨论可以把明确的新要求送给关联原任务，不能选择其他来源的会话或扩大原权限；旧写入提议被替代后仍需按更新要求重新规划和确认，不能默认批准旧动作。

## 参考与取舍

实际读取了[OpenAI Agents SDK session memory示例源码](https://github.com/openai/openai-cookbook/blob/01c41eeb5a83c87ec4202f9373a31902069c3e23/examples/agents_sdk/session_memory.ipynb)：`TrimmingSession._trim_to_last_turns`从后向前找用户轮次边界，在锁内维护有界会话。HomeBase采用“保留完整工作单元、按需组织上下文”的思想，但不照搬其删除历史存储的行为；执行账本和检查点必须完整保留。

[Anthropic上下文工程说明](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)强调有限上下文与按需检索。此处据HomeBase现有结构实现有界事实视图，不因此新增一套记忆库、代理框架或权限体系。

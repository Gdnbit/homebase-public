# 连续办事、主动跟进和长期记忆

桌面与微信共用原助理引擎、加密状态、权限和任务记录。本页说明新增行为，不要求调用方阅读源码。基本任务接口见 [任务工作流](assistant-task-workflow.md)，本机操作见 [本机工具](assistant-local-tools.md)。

记忆纠错、事件触发、通知筛选和执行中修改的完整接口见 [适应与跟进](assistant-adaptation.md)。新的工具参数从 `homebase-da-20261113.6` 开始提供，旧检查点保持原契约。

## 长期记忆

- 新任务实际开始时，自动检索最多4条相关有效记忆，总标题与正文最多1800字符；排队任务开始时读取，恢复沿用原检查点。
- `homebase_memory(search)` 使用离线中英文关键词与中文相邻字排序。精确匹配优先，标题与覆盖影响排序。没有调用 embedding 服务，不等同于语义向量检索；没找到时换具体名词查询，不能编造偏好。
- 查询只返回当前版本，到期或日期无效的记录排除；空查询查看最多12条当前记录。
- `remember` 遇同标题不同内容返回 `MEMORY_CONFLICT`，不创建矛盾副本；先核对旧内容，用原 `id` 更新并等待本人确认。到期记录也须指定原 id 更新。
- 当前模型工具更新时省略 `expires_at` 会保留原日期，明确 `null` 才清除日期；已到期的原日期不会自动延长。桌面/CLI 的 `assistant_memory_save` 是完整表单保存，应回传所查询的原 `expires_at`，明确清除时传 null。旧版检查点保留其原契约，不静默迁移待确认的操作含义。
- 最多保留5次内容/到期变化记录。`assistant_personal_get.memories[].previous` 供桌面查看历史，`origin` 记录最近更新来源和轮次；旧数据没有这些字段时正常读取。删除记忆一并删除更新历史，既有聊天和任务检查点单独保留。
- 普通对话不逐句自动归档。用户明确提出长期偏好时才提议保存；保存、修改和删除仍需本人确认。记忆正文不是操作授权。

## 重复失败与恢复

Pi 使用宿主的失败保护。同工具、同参数的确定失败附结构化 `recovery`，提示核对条件或修改方案。纯查询/参数校验最多3次；写入、终端、MCP调用、Skill执行等可能有副作用的操作失败后，不允许原样再执行，避免重复部分结果。新鲜读取仍实际查询，不复用上次内容。

触发保护为 `needs_input`，保留原步骤、结果与检查点，不声称完成。明确“继续”可开启下一次有限尝试窗口；原成功工具调用通过原编号和账本恢复，未知模型或副作用结果不重试。修改参数不代表得到新权限。

开发中的宿主修复保留失败计数，继续和第33种失败都不再清空原依据。继续后已拦截调用以 `TOOL_RETRY_BLOCKED`、`executed=false` 反馈给原图，可改为查询原结果或修正方案；同一次继续中相同工具/参数只给一次反馈，模型只换调用编号再提会停止，避免空转。台账满额保留原依据并要求拆分后续工作，不删除历史。最新隔离验证与部署状态见失败台账计划及[模型恢复约定](assistant-model-reliability.md)。

终端未收到终态、MCP 调用结果未知或本机宿主断连，分别保留 `EXECUTION_UNKNOWN`、`MCP_CALL_UNKNOWN` 或 `LOCAL_RESULT_UNKNOWN`，业务状态为 `unknown`。控制层任务结束不代表操作成功，也不能据此判断未执行；查询原编号、进度与产物，核对前不更换编号重跑。已知参数错误仍返回 `failed`，不会把未知包装成普通失败；返回给模型的错误不包含原始宿主异常或凭据。

## 主动办事

`homebase_reminder` 只到时提示；真正“到时检查/处理并返回结果”使用 `homebase_followup`，会调用助理执行任务，复用原通道的进度、确认、结果与附件交付。

模型工具：

1. `homebase_followup(action=list)` 获取独立 `revision` 与 `entries`，不能使用个人记忆的 revision。
2. `create` 提供 `revision,title,instruction,due_at,max_runs`，可选 `interval_minutes`；具体事项与时间明确后等待本人确认。一次任务 `max_runs=1`；重复最多30次，间隔5至43200分钟，首次在未来30天内。日期用含时区 RFC3339。
3. `list` 的 `runs[].turn_id` 为原任务；用原轮次查询/继续接口取实际状态和结果。创建成功仅证明安排已保存。
4. `cancel` 提供 `revision,id`，确认后取消后续执行；已受理轮次保留。停止当前任务另用原 `turn_id`，不能把取消计划说成业务取消成功。

外部 CLI / 桌面：

- `assistant_personal_get` 增加 `followups:{revision,entries}`，保留原 `revision,memories,reminders,skills`。
- `assistant_followup_save(request)` 创建桌面主动任务，输入与上述字段相同，不含 action/id。需要 write/private/external，调用前有用户对具体计划的授权。
- 新轮次可选 `matter_id`，把已确认计划关联同来源的持续事项。受理任务时原子保存关联，重启不重复执行；事项标题/目标/下一步变化、暂停或关闭会阻止旧计划继续受理。进展笔记变化不暂停计划，已受理任务仍保留。旧检查点保留原工具参数，详见 [交流与持续事项](assistant-conversation-and-matters.md)。
- `assistant_followup_cancel(followupId,revision)` 取消后续执行，需要 write/private。模型不能经通用调用绕过本人确认。
- 精确参数用 `hb describe`。原“记忆与提醒”弹窗展示主动任务、执行状态、记忆更新历史，并可取消后续执行；打开页面不会创建、恢复或重跑任务。

### 自动执行边界

只接受已启用 Pi 的明确免费 OpenRouter 路由，且 `free_only=true`。不自动启用模型，不切换 Key 或回退付费渠道。模型设置或本机授权版本改变时暂停并通知核对；每次工具操作仍遵守原确认规则。

应用必须运行，微信任务还要求原绑定通道在线。断连、停止、解绑撤销新执行的在线资格，重连后再检查；已受理任务不因断连被伪装为取消。退出期间不执行，超过原计划24小时不补做，暂停并提示重新安排；重复任务跳过积压，只计算下次未来时间。

离线微信的定时计划和已准备但尚未受理的请求等待原通道重新上线。通道恢复时检查原计划，连续收到同一在线通道的心跳只续期。桌面提醒、长期记忆到期、事件截止和已受理任务仍按原时间检查。

每次执行先持久化稳定请求编号，再受理并绑定原轮次。受理前崩溃恢复同一请求；受理后链接保存失败，从原编号找回，不创建替代任务。未知或失败会暂停后续重复执行，不无限重试；不允许主动任务递归安排主动任务。

准备后、受理前微信断连时保留原请求和执行时间。原通道重连时再尝试受理。需要新会话时与首个受理轮次一并保存，等待时不会产生空会话。桌面只把有原轮次编号的执行计入已受理次数。

微信结果复用原附件校验与发送。通知先持久化领取；发送 unknown 或领取后崩溃不自动重发。accepted 仅证明接口接受，不证明手机已读。其他来源不能查询或确认；有多个任务时，短确认仅处理来源内唯一待确认操作。停止/查询有歧义会要求明确目标，不任选一个。

最多50条主动计划（含历史），每计划最多30次；会话、总状态、模型预算沿用原上限，容量满时暂停并保留旧数据。本轮没有安装系统服务或开机启动，尚未提供任意事件条件监控、无限跨天自治或向量记忆。

## 设计依据

沿用 LangGraph 对 [线程检查点与跨线程长期存储](https://docs.langchain.com/oss/javascript/langgraph/persistence) 的区分；参考 Anthropic 的 [上下文按需组织原则](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)，限制自动召回的相关性与体积；参考 OpenClaw [持久化调度、唤醒 Agent 和结果交付](https://docs.openclaw.ai/automation/cron-jobs) 的闭环。这里按 HomeBase 权限和免费策略实现有限版本，不宣称整体能力等价。

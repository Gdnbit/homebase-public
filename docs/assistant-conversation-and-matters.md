# 工作中的交流、进度与持续事项

桌面与微信复用同一引擎、模型配置、任务证据及事项存储。微信仍绑定本人来源；桌面可管理本机事项并查看微信事项。不会因开启新对话而删除任务或事项，也不会把其他微信来源的资料带入当前对话。

## 边做边聊

`assistant_send(request)` 可选 `mode`：

| 值 | 行为 |
| --- | --- |
| `auto` 或省略 | 明确的讨论请求随时进入只读交流。其余消息在空闲时按正常助理流程处理。工作中由一次有界模型判断回复、修改原任务或把独立事项排队。判断过程只使用对话路由工具。 |
| `chat` | 只读讨论，模型不带操作工具；不修改任务、偏好、事项或权限。模型错误提出工具也不会执行。 |
| `task` | 明确提交另一项执行要求，工作未结束时按原FIFO队列处理。在途修改使用自动交流或显式 `assistant_turn_steer`。 |

桌面输入框的“消息方式”可显式选择。微信可说“聊聊这个制作安排”“为什么这样做”，也可以直接问普通问题。回复通常先说实际情况和下一步；只读讨论不会改变执行要求。另一件事要明确排队时可说“另外还有一件事”，桌面可选择排队任务模式；确定性修改原任务可使用 `assistant_turn_steer`。

自动模式下，「先聊聊方案」「请先讨论剪辑范围」「只讨论这一步」在空闲和工作中都进入只读讨论。提到素材和剪辑范围也可以先讨论。问「确认？」会保留原待确认操作。明确的「确认」继续由原确认流程处理。

讨论单独保存 `turn_id`、`interaction=chat` 和 `parent_turn_id`，沿用原 request_id 去重；讨论完成不抢走原任务的进度/确认目标。最多同时一个讨论轮次，讨论后的讨论不必等主任务完成。总运行并发仍为4，满载时需要等待；不是无限并发。讨论也使用所选模型，正常请求可能产生对应费用；免费模式、凭据来源及不回退规则照旧。模型请求未知时保留原记录，不自动重试。

自动判断的内部路由工具有 `homebase_queue_message({})` 和新运行时的 `homebase_steer_message({})`。前者将原消息转为同编号后续任务，后者把原文记入绑定的原任务，在安全节点处理；两者不能替换用户正文、直接执行业务或批准确认。成功收件的修改回复保留 `interaction=chat`，并以 `steered_turn_id` 明确标记，桌面不会误标为只读讨论。保存失败不执行；重复消息复用原收件。失败/停止/重启后的独立执行队列仍须明确继续。显式聊天没有这些路由工具。旧任务不支持在途修改时明确拒绝，不迁移原检查点。

微信引用可指定当前绑定内的较早助理任务。已核实的任务编号和文件身份先进入受保护的微信收件，随后以同一请求编号进入原任务所属会话。仅活动中的被引用任务可成为修改目标。已完成的被引用任务提供有界上下文，新的工作仍走原队列和确认规则。引用附件提供文件名、产物和任务标识等已登记信息，读取、编辑或发送仍由相应能力核对。引用正文和旧任务摘要作为背景资料。 [OpenClaw 的指定消息引用](https://docs.openclaw.ai/web/webchat) · [腾讯入站引用解析](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/inbound.ts)

## 具体进度

`assistant_turn_get` 增加 `progress`；微信查询结果增加 `progress_details`。字段为：

- `goal`：本轮目标。
- `completed`：已完成阶段/可核验成功步骤的简短名称。
- `current`：当前阶段或真实工具动作；无在途执行时为空。
- `blocked`：待确认、缺少条件、预算停止或结果未知的具体说明。
- `next`：计划中待做步骤/恢复条件，不代表已经执行。
- `completed_stages` / `total_stages`：计划阶段数，不是估算耗时百分比。

普通微信回复不自动附终端日志、工具名、任务UUID或未核验百分比；CLI/桌面详细工具结果仍可查。原生终端的实时输出由已有 progress 接口提供。完成、附件安排发送、微信接口接受和手机收到分别核对。

可说“进展怎么样？”“做到哪一步了？”或“现在在做什么”；这些短查询不新增模型推理或业务执行。有多个执行目标时仍要求明确目标。

助理轮次已结束、原业务任务仍在途时，桌面「核对原任务」和微信查状态或取结果都会先核对原会话，再查询该任务原编号。查到可验证的结果后，可在原会话查看已有产物。若模型的受理状态仍未知，模型提示和原轮次状态保持。普通桌面进度读取沿用原轮询路径。

候选版本中，停止等待后的桌面恢复入口会统计完整的关联任务，包含精简列表八条之外的自有任务。一个任务暂时查不到时，其他任务仍可核对，已确认的产物仍可查看。桌面会说明本次有多少项未查到最新状态，可以再次核对原编号。该提示属于本次查询，不会覆盖原任务状态。

## 持续事项

一次执行任务、长期偏好、提醒与持续事项不同。事项用于记录一个跨对话目标，例如动画发布、等待审核的材料；完成其中一次执行，不会自动把整个事项标成完成。

模型工具 `homebase_matter`：

1. `list`：可选 `query`，返回独立 `revision` 和 `entries`，只读当前来源事项。桌面本人可查看本机及微信事项。
2. `get(id)`：返回原记录及最新关联任务的真实状态/结构化进度，不重新执行。
3. `save`：完整提供 `revision,id,title,goal,summary,next_action,state,review_at`，等待本人确认。新记录 `id=null`；同名记录先核对原id，不静默创建冲突副本。
4. `attach(revision,id)`：经确认把当前执行轮次关联到原事项，不能传任意 turn_id。最多64个关联任务，已确认定时任务的剩余次数会预留名额；不删除旧关联或创建替代任务。

`state` 为 `active`、`waiting`、`paused`、`completed` 或 `canceled`。`summary` 是上次确认的进展笔记，不能当成业务执行证据；最新关联任务另列。保存/关联都要核对版本；内容有变化时重新查询并确认，不覆盖新记录。最多50条事项，保存最近5次进展/下一步/状态变更历史；没有自动清理旧数据。

`review_at` 是可空、含时区的 RFC3339 复查时间，新增/更改须在未来一年内。完整表单更新应回传原时间；明确 null 清除。关闭、取消或暂停事项停止复查。到期只提醒用户回顾，不调用模型、不执行后续任务、不修改密钥。到时实际办事仍用 [homebase_followup](assistant-continuity.md)，另行明确安排与确认。

新轮次的 `homebase_followup create` 与桌面 `assistant_followup_save` 可选 `matter_id`：须先读取同来源的未关闭事项，再确认具体执行内容、时间和次数。受理时原任务与事项关联一起持久化；重启对账只补关联，不重复执行。事项标题、目标或下一步改变，以及暂停/关闭事项，都会阻止旧计划继续受理；只更新进展笔记不会取消约定检查。已受理的任务仍保留，若要停止正在进行的工作须明确停止原任务。关联不增加任何文件、终端、模型或其他工具权限。

复查默认回到创建来源：微信事项回原绑定微信，桌面事项在个人面板显示到期。已领取通知先持久化，发送未知或领取后崩溃不重发；新时间经确认保存后才重新安排。桌面“已知悉本次复查”只确认通知，不把事项标成完成。应用关闭期间不运行，重开后检查一次到期项目。

微信可说“持续事项”“待跟进事项”“还有哪些事”查看待办，不新增模型请求；列出最多8条，可按名称进一步查询。新对话里可使用：

- `进度发布动画` 或 `进度 发布动画`：优先查询正在执行的原任务；没有在途任务时，显示可恢复任务或最近一次检查。
- `结果发布动画`：优先取得已有附件的原结果；后续只读检查不会遮住原附件，不重新生成。
- `继续发布动画`：沿用该事项在途或可恢复原任务的检查点；已完成或不具备安全恢复条件时明确拒绝，不新建替代任务。

名称精确匹配，来源必须一致。尚未关联执行任务时会说明只有事项记录，并询问本次要做什么。新对话本身不构成对旧任务的确认。长期事项不会把另一微信来源、其他桌面私聊或无关任务变成可操作对象。

## 桌面与外部 CLI

个人面板显示事项目标、上次确认进展、下一步、复查状态、历史和原任务状态；页面打开/切换只读取，不恢复或执行任务。

桌面助理顶部的「记忆与提醒」用红点提示待知悉的普通提醒和持续事项复查。桌面到期或微信发送结果待核对时显示，确认最后一条后消失。读屏软件可获取同一状态。微信主动办事卡片单列通知状态，分别显示等待发送、发送中、微信已受理或发送结果待核对。微信已受理表示发送接口接受了请求，手机是否收到仍需在微信核对。

关联原任务的状态或实际进度变化会通知面板更新；单纯保存运行计数/检查点不会使整个个人面板重复加载。

- `assistant_matters_get()` 返回本机事项清单；`assistant_personal_get.matters` 为同一份数据，独立 revision。
- `assistant_matter_save(request)` 是桌面完整表单保存，需要 write/private；调用方须有用户对具体事项的授权。
- `assistant_matter_review_ack(matterId,revision)` 知悉桌面到期/未知复查，需要 write/private。
- 具体嵌套字段和大小限制使用 `hb describe`；与原记忆/提醒/followups 的 revision 不混用。

旧运行时检查点沿用旧工具集及到期语义，新工具只用于新轮次。不借此升级依赖或修改模型、Key来源、授权目录、系统服务。

## 当前边界

这是对持续交流与事项跟进的增量实现。尚无云端常驻、任意事件监控、自主选择唤醒时刻、跨渠道任意历史搜索或多专家并行委派；现有来源隔离也保留。自然语言判断和回答质量仍取决于所选模型，合成模型回归不等于任意真实模型都能理解所有表达。与 [Dot的持续职责定位](https://learn.chatgpt.com/docs/dots/tasks-and-memory) 相比，已接入本机能力与状态闭环优先，未宣称全功能等价。

# 助理桌面输入与受理恢复

本模块管理未发送输入和客户端回执；会话、任务、审批和业务恢复仍由原助理引擎负责。桌面与微信的共享默认模型、真实密钥和个人状态不迁移。

## 用户体验

输入框保存正文、消息方式、本次模型选择和有界文本附件。后台缓冲保存；只有后端确认后才显示“草稿已受保护保存”。未确认内容不能按已保存处理。失焦和正常关闭会尝试保存；保存失败时正常关闭会提示，强制结束进程仍可能丢失尚未确认的修改。

关闭期间如果继续输入，窗口会等待最新版保存。助理、资料收录和开发草稿共用 10 秒保存期限，失败或超过期限时可返回编辑器保留本次输入。实际窗口、重开及旧版回读见关闭保存验收。

桌面侧栏底部的「退出 HomeBase」和系统标题栏关闭共用上述保存流程。两处同时触发时，当前保存或确认继续处理一次。应用内入口直接启动该流程，关闭按钮的系统事件尚未送达时也可使用。日常版是否已经包含此入口见 当前验收和上线状态。

候选前端在发出关闭请求后保留进度。窗口十秒后仍在时，会区分「退出请求仍未得到回应」和「退出请求已受理，窗口仍然打开」。这两种状态下，侧栏和标题栏共用同一次请求。原生接口明确返回失败后，可以再次退出。 关闭回执验收

助理草稿、资料收录的首次加载和开发草稿刷新仅在读取且没有未保存内容时，关闭窗口无需等待读取。正在保存、上传、发送、更新原回执或写入旧开发请求时仍走关闭保护。

开发中前端允许在模型关闭时编辑已恢复的可写草稿、准备本地文本/PDF，仍不允许发送或启动语音；Enter用于换行。配置读取失败不使用缓存启用发送。附件读取完成按最新草稿合并与校验，取消/离开不加入迟到结果；读取期间移除的文件不会恢复，容量失败保留原附件，待核对请求不被附件结果修改。PDF摘录沿原document_id替换且保留其他引用。最新界面及部署状态须查看草稿验证记录，不由源码存在推断日常程序已更新。

文本附件可以在读取过程中取消。取消后焦点回到输入框，可继续编辑、发送已有内容或重新选择文件。切换会话或离开助理也会中止原读取。每批文本附件全部读取并通过校验后才加入草稿，取消一批不会清除此前已加入的附件。 附件取消验收

内置桌面输入支持单张本机 PNG。通过添加附件、拖放或粘贴准备图片后，输入框保存附件引用并进入「只聊聊」。发送前输入 1 至 4,000 个 UTF-8 字节的问题，确认具体的 OpenRouter 视觉模型。同一消息只携带图片和本条问题。免费模式要求明确的免费视觉渠道，不切换渠道。切换会话、退出或查回执只保留或读取原引用。后续普通消息不再次附加这张图。

新输入区开始交互后（聚焦、拖入文件或采用提示词），后台迟到的会话列表不会自动把输入入口切换到旧会话。自动恢复选择读取当前内存草稿和原回执，已输入内容不依赖旧渲染快照判断；显式选择旧会话和已确认发送后的原会话续接仍有效。这是输入归属保护，不会启动任务或改变已有任务状态。

未发送正文最多64KiB（UTF-8字节），与实际消息8,000字节上限分开。长中文可以先安全保存，再缩短或改为有界文本附件后发送。输入区按字节提示超过发送/保存预算；后端独立校验，超发送上限不会写入准备回执或执行。超过保存上限明确尚未保存，保留原密文，不静默截断。原生文字草稿也遵循同一保存容量，原适配器发送预算不变。

“更多对话操作 → 未发送与待核对”按需读取已保存摘要，可打开对应输入。坏密文明确提示，不当作空列表，也不覆盖原文件。版本冲突时保留本窗口输入，可查看已保存版本，再由用户明确选择是否替换。

发送前持久化原请求；失败则不执行。网络响应丢失时保留原 request_id、消息方式、模型和附件。“查询原请求”只查已受理编号，不重做任务；未找到不等于取消。明确重试仍使用原编号。已经受理但本地清理失败时保留 ack 和警告，不提示用户换编号重发。查询确认后只清理原内容，用户后来输入的文字保留。

## 接口

| 命令 | 参数 | 结果与边界 |
| --- | --- | --- |
| `assistant_desktop_index` | 无 | 已保存摘要、`complete`、`unreadable`；不返回正文 |
| `assistant_desktop_get` | `scope` | `entry.revision/body/pending`；缺失返回 revision=0，不写盘 |
| `assistant_desktop_save` | `request:{scope,revision,body}` | CAS 保存；同内容幂等，旧版本不覆盖新内容 |
| `assistant_desktop_image_stage` | `scope,name,pngBase64` | 加密准备一张 PNG，返回 `{scope,name,sha256,bytes}`；需要 `write` 和 `private` |
| `assistant_desktop_send` | `request,revision` | 原 `assistant_send` 请求格式；先持久化后提交；检查 `ack` |
| `assistant_desktop_resolve` | `scope,request?` | 原请求回执核对；响应丢失后可带完整原 request；从不发送或恢复业务 |

`scope` 为 `new`、已有桌面会话的规范 UUID，或 `native:codex|claude-code|gemini-cli:原生ID` 的本机输入命名空间。原生ID允许1至120位ASCII字母数字、连字符与下划线，不假定UUID；命名空间不授予原生读取/执行权限。微信会话在桌面只读。`body={text,route,mode,files}`，内置助理mode为auto/chat/task，files最多4个、每个16KiB、总32KiB；原生草稿当前只支持text，其余字段保持route空、mode=auto、files空，未适配字段明确拒绝。状态索引最多200个scope，达到上限明确失败，不静默丢稿。send/resolve仍只处理内置桌面原请求，`ack.turn_id` 用 `assistant_turn_get` 查询业务终态；原生发送沿用其适配器。

`status=failed` 必须检查 code/message；`status=partial` 且有 ack 表示已受理，仅本地收尾未确认。不得把 partial 映射为没有执行。自动恢复只查询、绝不提交；待核对回执不按时间静默过期。内置模型不能递归调用这些入口。

## 存储和限制

每个 scope 保存独立的 Windows 当前用户 DPAPI 密文，目录为 HomeBase home 下 `.homebase/assistant/desktop`。文件名取 scope 散列，写入前设私有 ACL，原子发布；进程锁和文件锁避免并发覆盖。新格式坏密文或版本不匹配时失败关闭，不回退明文或空状态。没有浏览器 localStorage/sessionStorage 草稿副本，也不额外引入加密主密钥。

正文和附件在本机解密后进入当前输入；用户主动发送后才进入已有执行引擎。原生文字草稿与冻结发送编号共用同一存储，通过 `assistant_native_send/resolve` 核对原适配器回执，详见[原生发送](assistant-native-receipts.md)。录音/ASR恢复见[语音状态](assistant-voice-recovery.md)。PDF、图片与真实流式协议不从本模块推断可用。

PNG 原文件最多 384 KiB、每边最多 2,048 像素、总计最多 2,097,152 像素。图片会被完整解码并重新编码，去除来源元数据。加密图片独立存放在 `.homebase/assistant/chat-images`，相同范围和内容复用原文件，最多 256 张，达到上限保留已有文件。移除草稿附件只解除引用，当前没有清理独立密文的入口。会话交接保留原图于原会话。分段会话备份保留当前、待核对及已受理轮次的图片，使用文件清单按项取回。 [图片备份与取回](assistant-archive-backup.md#取回草稿录音与图片)

已受理的图片轮次在加密检查点记录原引用及发送尝试。新版能确认请求尚未开始时沿用原轮次继续。发送后结果未知时继续核对原编号。v117 保存其他会话时保留该检查点，遇到未发送图片轮次会暂停到待核对状态。回到新版可按原回执查该轮次并备份原图片。含 PNG 的未发送草稿仍使用新版编辑。 已受理轮次往返验收

CLI 使用 `hb describe assistant_desktop_image_stage` 查完整参数。把返回的引用原样放在 `assistant_desktop_save` 的 `request.body.image`；`body.mode="chat"`、`body.route` 为所选视觉路由、`body.files=[]`。显式发送时以原草稿版本调用 `assistant_desktop_send`，传原 `request_id`、相同的 `route_id`、`mode`、`text` 和 `image`。回执丢失先调用 `assistant_desktop_resolve` 或 `assistant_send_receipt_get`，再以已确认的 `turn_id` 查询完成结果。

当前隔离验收及部署状态以 持续 Goal 工作记录 为准。

## 工作流交接（开发中，未更新日常程序）

资料、文稿、快捷输入、能力选择与会话交接共用独立草稿准备流程，不自动发送或调用模型。完整正文先保存到`handoff:<规范小写UUID>`的OS保护暂存，再用`assistant_session_create({requestId:UUID})`准备同ID的真实桌面会话，确认目标草稿保存后按原正文/CAS清理暂存。暂存清理失败保留副本；创建或保存回执丢失后从原暂存/原UUID继续，不换编号盲建会话。暂存只允许文字、route空、mode=auto、files空；仅get/save/index接受，不授予发送、文档、录音或原生执行权限。

重启后“未发送与待核对”可继续待转入暂存。已使用的目标会话只打开原会话，不重新填入旧任务；不同正文、模型选择、待核对请求或录音均阻止覆盖。切页、切换原会话或保存期间继续编辑，不让迟到响应抢走当前工作。兼容旧draft链接时，已有正文须显式确认合并，超64KiB或待核对状态保留两份输入；新入口只传会话ID，不把原文放入URL或导航state。

Inbox只携带当前原文、标题、标签、来源和已有附件引用，不读取或上传文件；先前投料未知须查询原记录。Studio携带有界摘录及完整未发要求，原运行任务仅交接session/task编号用于查询，不取消或重复生成。摘录有界不表示历史完整，长草稿仍遵守发送8,000字节限制。现有100会话/200草稿范围保护保持，长期容量与暂存清理策略另行完善；不能宣称无限历史。

旧版本不识别handoff范围，回退前须提供兼容版本或明确保留不可读原文件，不用旧快照覆盖。实施范围及验收见交接计划和当前验证记录。

已完成的空交接副本仍保留原revision，移到同一受保护存储的`completed-handoffs`目录，避免永久占用活跃200范围和反复索引解密。只移动规范handoff、默认空body且无任何请求/录音的已保存副本；其他草稿保持原布局。get在没有活跃文件时读取原完成记录，重新激活继续递增版本，旧窗口不能利用文件删除后的版本重置覆盖新输入。坏活跃文件不回退完成区，坏完成记录不回退版本0。移动失败保留原位置的已清空文件并明确错误，不撤销已保存目标；修复阻碍后可同版本重试收尾。

索引的complete/unreadable针对活跃范围，已完成空副本不作为待恢复任务列举。活跃200范围仍保护，不静默截断或删除；完成区元数据仍占用磁盘，后续压缩/长期容量另行验收，不能称为无限存储。开发、隔离验证及上线状态仍以上述记录为准，方案见已完成副本容量计划。

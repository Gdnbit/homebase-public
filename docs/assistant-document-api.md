# 受控 PDF 接口

当前接口仅处理本机 PDF 文字，不做 OCR、图片理解或云端解析。来源至多 4 MiB，单次提取至多连续 40 页，提取文字至多 256 KiB。文字、页码和诊断保留来源摘要；文件内容不构成指令或授权。

普通 AI 从 `control/START.md` 进入，通过 `describe assistant_document_import` 等命令获得实际参数契约。所有命令都要求明确的输入作用域 `scope`：新对话为 `new`，已有桌面对话使用其 UUID。模型工具不能自行指定这些作用域或读取未发送的草稿。

CLI 可直接运行 `hb documents import --file PDF --document-id UUID --scope new --allow-write --allow-private`，帮助器只读明确选择的文件，按分块接口导入；保留原 UUID 和原文件即可续传。它不启动解析，也不将本机路径传给后端。后续仍按以下提取、查询和摘录接口完成操作。

1. 为一个文件生成稳定的 `document_id` UUID，计算原始字节 SHA-256。按 256 KiB 分块调用 `assistant_document_import`，每块使用相同的作用域、编号、文件名、摘要、总字节数，`part` 从 0 开始。参数传字节的 Base64，不能传本机路径。不要通过输出或日志暴露原文。
2. 中断后调用 `assistant_document_import_status`，仅补充 `missing` 中的原分块。`complete` 只表示分块存在；尚不表示完整性校验或注册成功。相同编号的不同内容会被拒绝，原分块保留。
3. 调用 `assistant_document_import_commit`；它重新解密所有块并核对来源 SHA-256，成功后才注册文档。失败不会启动解析。相同原文件重复提交复用现有来源。
4. 调用 `assistant_document_extract`。`pages` 可省略；超过 40 页时必须按返回说明明确选择页范围。`started` 表示开始监督本地进程；`capacity`、`runtime_unavailable` 表示没有启动。它们不是业务成功。
5. 查询原 `extraction_id` 的 `assistant_document_status`，结束后调用 `assistant_document_result`。`ready` 才能使用文字；`no_text` 明确表示没有提取到文字，不能当成空字符串成功；扫描件需要其他已适配能力。`unknown` 不代表失败或取消，不自动重做。
6. 用 `assistant_document_excerpt` 明确选择已提取页和可选 UTF-8 字节区间。返回 `{name,content,document}` 可作为普通助理附件。单附件含来源说明仍须不超过 16 KiB，整条消息继续遵循既有附件和发送限制。正式发送会重新核对内容、来源及会话归属；不能伪造引用或跨会话读取。
7. `assistant_document_cancel` 只取消当前进程实际监督的原任务。`cancel_requested` 尚未确认停止，继续查询原编号；`not_running_here` 不声称已经停止其他进程。重启后仅查询恢复，显式重试也必须通过原任务锁和状态检查。

`assistant_document_index` 返回指定会话可见的文档来源。桌面输入另有未提交上传列表。`assistant_document_get` 返回某来源的提取摘要。列表、打开窗口和查询均为只读。来源字节、分块、摘要和结果使用本机受保护存储，不复制现有密钥或配置。

此文描述接口；桌面 PDF 选择、预览及模型专用工具的实际验收以最新带日期验证报告为准，不能根据接口存在推断所有入口已经接通。

桌面可以在模型关闭时先准备草稿和附件，不会自动发送。文本编码或附件预算失败会保留原输入；打开 PDF 预览、提取文字或失败重试不等于已解决输入错误。摘录通过来源、可写性和附件预算检查并成功加入后，才清除先前的输入错误；附件满额时可先移除不需要的附件，再加入已提取摘录，无须重新解析。验证范围见附件恢复验收。

候选 v72 的 PDF 面板将状态重查、文字重查和重试解析分别处理。状态读取失败时暂停轮询，「重新查询」读取原编号。「显式重试本地提取」沿用原记录的范围，当前编辑的页码用于新的「提取文字」操作。验收见PDF 恢复记录。

关闭桌面 PDF 面板会结束后续未发出的分块请求。已发出的分块或提交回执结算后，原会话的文档列表会更新。重开能看到已保存的分块或已登记的来源。同一会话有原导入操作在结算时，等待结束后再选择原文件，继续其缺失的分块。提取文字、加入草稿和发送仍由各自的明确操作触发。 导入续接验收

提取、显式重试和停止以会话和文档为范围保持同一个在途操作。关闭或切页后重开，会等待原操作回执并按原文档刷新提取记录。即使界面回执丢失，已经保存的原记录也可读回。后台结算带来的刷新只读原文档，已关闭的面板在下次打开时读取。加入摘录和发送仍需要用户操作。 提取回执恢复验收

模型专用工具 `homebase_document` 支持 `list/read/extract/status`。`list` 按最近发送顺序列出本轮及此前已正式发送的用户消息引用，以 `offset/limit` 分页，默认10条、最多20条，返回 `total/next_offset`；长名称可能使实际页更小。`read` 默认仅返回最近一次正式发送的原摘录，使用 UTF-8 字节 `offset/limit` 分页，默认 6000、至多 8000 字节；实际窗口会为 JSON 转义留出空间，必须按返回的 `next_offset` 续读，不能按请求的 limit 自行前进。需要同一已发送来源的其他页时，`extract` 必须指定明确页范围，不接受宿主路径或自动重试；来源字节留在本地，读取的文字才作为资料进入模型。新的运行协议为 `homebase-da-20261113.7`，已有 `.6` 及更早检查点保留原工具集，不插入新工具或迁移旧任务。

桌面可以准备当前输入的暂存来源，助理能使用已在消息中提交的文档引用。通用 `homebase_call` 不能绕过专用文档工具访问 `assistant_*` 接口。绑定本人单独发送 PDF 时，微信入口本机保存并解析首页，桌面原微信会话可只读查看。微信收件正文不自动进入模型上下文。候选入口允许用户在原会话明确引用该收件提问，提交有来源及页码的首页摘录，并沿用只读讨论和原请求回执。原生 Codex/Claude/Gemini 文档附件及 OCR 仍待适配。 [微信引用方式](wechat-integration.md#引用-pdf-后提问候选)

# 助理文档引用与会话归属

状态：引擎引用、有界摘录、公共分块上传/提取、模型文档工具及桌面预览已接通，并通过同一隔离程序的原生串联验证；见接口与验收。真实运行环境尚未部署该新程序，不提供猜测其他会话文档标识的捷径。

`assistant_send`、受保护桌面发送及草稿中的TextAttachment保留原{name,content}。可选 `document` 是服务端既有摘录的完整引用，含document_id、extraction_id、source_name、source_sha256、page_from/page_to、text_from/text_to、content_sha256。文本偏移按UTF-8字节而非UTF-16字符；原生Codex/Claude/Gemini的文字接口仍不接受附件。

调用者须原样使用服务端准备的name/content/document，不自己拼摘要或猜编号。引擎在创建会话/调用模型前核对真实归属、原提取、页/字节范围、完整来源说明和内容摘要。引用是资料标识，不能授予工具权限；PDF文字和文件名也不构成指令/授权。附件预算仍为最多4个、每个16KiB、合计32KiB。

完整页面文字可能超过附件预算：服务端会拒绝并要求明确缩小范围，不能静默截断。可显式选择连续页及其中UTF-8边界内的文字，来源说明标明partial；保留中文/emoji，不把文字提取称为OCR/视觉理解。使用 `hb documents import` 和 `assistant_document_extract/status/result/excerpt` 准备服务端摘录，具体参数、恢复规则及模型读取边界见[公共接口](assistant-document-api.md)。

## 归属规则

源记录不可变，保存origin_scope。尚未发送的new来源属于新草稿；发送受理时，现有引擎把文档引用与用户消息、原请求指纹一并原子保存。这份消息附件是正式会话关联的唯一事实源，没有第二个绑定表或发送后再补写的确认窗口。

发送后实际session_id能访问原文档，new草稿不能再据旧origin_scope读取它；其他会话即使知道UUID/引用也不能访问。既有会话可访问其原始scope上传的资料，或已经被该会话真实消息引用的资料。读写适配器必须分别核验入口权限；客户端/模型不能提供“已关联/已被引用”的布尔授权。

引擎消息保存失败不会归档源或冒充受理；源和新草稿保留，核对原回执后才决定重试。已受理的稳定request_id在文档源后来不可读时仍返回原ACK，不因源校验错误重跑。换正文、路由、模式或文档引用必须构成不同新请求；修改旧编号内容会拒绝。

首次发送的候选会话与消息一起原子保存，消息保存失败不再留下空会话；桌面和微信共用该路径。公开context查询不存在的会话仍明确失败，不把内部候选当成已保存记录。

## 旧数据和客户端恢复

没有document字段的附件读取为None，序列化时该字段省略；旧JSON及旧发送指纹保持原字节格式。新增引用完整参与新请求身份。消息附件元数据保留来源和内容摘要，完整PDF字节不进入聊天协议；先发送用户明确选择的有界摘录，助理可经专用工具按需读取同一已发送来源的其他页，加入前界面明确提示这一范围。草稿和未来排队输入不属于当前模型的读取范围。

草稿ACK清理比较完整附件，包括引用。即使文字相同、后来修改了引用，旧ACK也不能清掉新内容。重启归属从已有消息附件恢复，不重建会话、不修改源、不重新解析，也不重新调用模型。

基础引用测试使用合成提取结果与实际引擎，真实PDF.js解析/进程测试见解析验收、状态验收。后续同一隔离程序已跑通实际CLI导入、解析、原生预览、摘录、草稿重启、正式发送归属和原ACK恢复；完整证据见公共接口验收，模型往返为合成模型测试，不冒称真实云端模型。

当前实际结果见引用与引擎验收。PARSER中的版本后缀同时标识当前提取/摘录约定；后续改变来源说明或偏移格式须版本化并考虑旧引用，不能就地修改既有内容使旧回执失效。

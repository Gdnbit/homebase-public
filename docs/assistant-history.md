# 历史分页和正文分块

`assistant_history_query`与`assistant_history_read`提供只读、有界的会话历史。原`assistant_session_get`保留完整兼容返回。它们不执行或恢复旧任务，也不把历史授权继承到新操作；实时任务状态仍用原轮次/job接口查询。

先按实际会话编号调用query，例如`request={session_id:"实际会话ID",kind:"messages",query:"项目",offset:0,limit:8}`。kind可选messages或turns；query最多240 UTF-8字节、无控制字符，按Unicode小写进行普通子串匹配。消息检索正文，轮次也匹配同轮消息；不搜索外部文件或自动展开附件。空关键词读取全部当前记录。

返回`version=homebase-history-v1`、原记录ID、预览、JSON字节数/哈希、总数和实际next_offset。预览始终标记`preview_only=true`，不能当成全文。续页保持原session_id、kind、query、through_turn_id与snapshot_id，用实际next_offset；limit为1至20，页面可能因字节预算而少于limit。无匹配历史明确total=0、items=[]、complete=true。

通过read指定原session_id/snapshot_id/item_id，从offset=0读取。limit为4至8192字节；实际内容可能因JSON转义后的预算缩短。严格按next_offset续读，偏移是原JSON的UTF-8字节位置，不是JavaScript字符下标。拼接content，直到complete=true，再核对total_bytes和json_sha256后解析完整JSON。format为message_json或turn_view_json；单块不必是独立可解析的原JSON。

每份结果序列化不超过9000字节，预算不包括CLI外层job/result封套；完整原消息/轮次不会被预览代替。CLI可用`hb describe assistant_history_query`、`hb describe assistant_history_read`读取自包含schema与模板，再按私人范围提交。模板中的编号必须替换为实际返回值。

历史快照固定记录编号、筛选结果和捕获时刻，后续修改不会混入原页或分块；它不是实时任务状态。5分钟无活动过期、最长1小时；只有成功且范围匹配的读取续期。最多4份，热记录或冷索引等来源总预算32MiB，已编码正文及预览元数据缓存64MiB；归档读取器复用原Store的32MiB/8段缓存，不为每个旧会话建立正文池。读取已缓存正文不会每次重编码全文。重启、过期、淘汰或条件/来源不符明确返回HISTORY_*错误，重新query，丢弃未完成拼接并从新快照offset=0读取，不混拼旧片段或静默换会话。坏偏移、无记录、坏源和容量超限各自明确，不退回空成功。

内置助理使用`homebase_history`，由后端绑定当前来源、会话及截止轮次，只读此前已归属内容。工具不接受session/source/path；无法确定截止归属的旧消息明确计入省略数。外部私人CLI可不指定through_turn_id以读该会话全部当前记录。新工具只为运行时`homebase-da-20261113.8`挂载，旧7及更旧检查点的工具集保持原样；新任务仍可查阅旧格式记录。

消息快照只读取所需会话的消息：空关键词且无截止时先冻结已验证编号，按页读取当前所需正文；截止轮次由受保护的原有序编号校验，不为此装载轮次正文或模型上下文。关键词/截止需要完整总数时逐段扫描，仅保留匹配编号；原快照续页不重复筛选。纯聊天轮次按冻结编号读取相应轮次，保留所选轮次首条原用户输入以确定原目标；建立该映射仍需扫描消息。闭合任务的轮次快照继续读取完整消息、轮次和job以核对归属，不用提示推断job权限。两类快照都不把只读投影写入实时执行状态。没有独立全文索引，不宣称搜索或轮次建图具有恒定读取成本。

续页和正文从已冻结快照读取，不重新装载当前冷会话；来源、条件、截止和租约仍须匹配。创建快照不表示所有原正文都已装入内存或检查完毕；已缓存字节可继续复用，未读分段按实际请求校验，损坏/缺失明确报错，不显示为无匹配或空成功。后续提交保留的原段继续按原引用读取，不能混入新值。重启后快照明确过期，不先读取旧正文再猜测恢复。

容量实验模式的活跃会话也能从原加密快照按完整顺序读取消息，包括早期已完成聊天和当前近期消息。单会话窗口按原消息 ID 定位，保留原总数。`assistant_session_get` 和任务轮次历史仍受完整投影预算约束。超过 100 个自有任务的同会话执行仍待接入。按需读取 · 活跃会话消息

上述冷读取适配用于已验证实验格式；日常程序是否启用以实际版本与部署记录为准，不据文档存在推断已迁移。桌面历史窗口另见[会话窗口接口](assistant-session-window.md)。跨会话模型搜索、完整冷化/迁移及长期容量仍需继续，原保护上限保留。历史快照不授予新的任务或文件权限。

## 超过单次 CLI 上限的原轮次

完整任务结果超出单次 CLI 上限时，用原会话和轮次编号运行以下命令。

```text
hb history read-turn --session-id <原会话ID> --turn-id <原轮次ID> --allow-private
```

该命令只冻结相应轮次，校验每块的来源、UTF-8 字节偏移、完整字节数和 SHA-256，再把验证通过的完整 JSON 写到标准输出。需要保存时，可把标准输出重定向到经用户授权的新本机文件。读取失败会返回错误 JSON。程序重启或快照过期后重新冻结同一原轮次。

分步访问使用 `assistant_turn_snapshot` 创建精确快照，再用 `assistant_history_read` 传入原快照、轮次与偏移。每次可请求最多 524288 个正文 UTF-8 字节，返回序列化预算为 1 MiB。常规会话历史和内置模型工具仍使用 8192 字节请求上限及 9000 字节返回预算。精确快照沿用 CLI 对结构化凭据字段的脱敏规则，在脱敏后生成摘要。实时状态和授权核对继续使用原任务接口。

# 原任务身份、归属与查询写回

助理读取任务时保留原job编号和命令。桌面、微信及原生Agent委托共享执行器时适用同一规则；会话编号、来源和原授权仍由既有适配器检查，不从提示词或结果正文取得权限。

`homebase_jobs`保存的是发现元数据。重复观察同一任务不会建立所有权，不占用自有执行名额，也不能据此返回文件。非自有私人结果仍需原命令的明确确认，只查询原编号；已发现编号若出现不同命令，明确拒绝，不择一猜测。

自有记录通过唯一job编号查找；重复编号报`JOB_IDENTITY_CONFLICT`，不挑选第一条或较新的结果。自有刷新及模型远端查询都核对控制返回的原id和command；缺失或不符报`JOB_IDENTITY_MISMATCH`，不采纳正文、登记附件或提交替代操作。此错误不表示原任务未执行，也不授权重做。

这些JOB_*标识是原助理错误消息中的静态前缀，不是新公开的命令或另一套任务状态。外层CLI error.code仍遵守原控制器错误映射；应同时读取message，不只检查业务返回是否为null。

结果归属同时核对功能来源：视频run_id来自本会话自有`capability_render`；仓库run_id来自自有`repo_capability_run`；已安装Skill的结果目录来自自有`assistant_local_execute`及原workspace_id/installed skill_id。不同功能恰好同名的run_id不是可互换凭据。通用文件目录、服务商任务或其他会话结果不能冒充上述引用。

查询开始时捕获原job，发布结果前在同一状态事务中比较该记录。若查询等待期间投递标记、远端查询进度或其他job内容已经更新，报`JOB_READ_STALE`，保留新状态；既有有界重试只重新查询原编号，不重新执行。比较针对该job，不因无关会话变化而丢弃有效结果。保存失败继续遵守原事务回滚；查询出错不伪造空成功或清除未知状态。

工作计划仅把唯一、自有、成功且非空的原job当作完成证据；重复编号不构成完成或投递证明。记录读取与结果绑定复用内部只读边界，保留现有数组格式、命令schema、运行时及确认规则。

准备调用时，助理在执行前保存已授权的原步骤和命令。待核对受理与已登记自有任务共用原会话名额。提交回执丢失或登记失败后，桌面轮次查询与微信原轮次查询使用内部控制账本核对原请求编号、命令及参数摘要，再登记原编号。控制账本读入口只返回已有受理，具体验证见任务回执验收。

账本核对失败或尚无匹配回执时，进度保留可核对状态。已有编号而控制正文不可恢复时显示结果未知。待核对期间原轮次不能继续执行。旧会话中缺少新持久标记的步骤继续使用原记录，已登记 job 的读取保持原有入口。

普通模式的 100 个接纳名额计入全部自有记录及待核对回执。容量实验模式会在原步骤和结果均可确认、且无需跟进或交付时释放名额。失败、未知、待交付和结果不完整的自有记录继续占用名额。已释放名额的结果仍按原编号保存，继续计入整体存储字节预算。

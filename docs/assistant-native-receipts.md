# 原生输入与发送回执

桌面 Codex、Claude Code、Gemini CLI 文字输入复用受保护桌面草稿。`native:provider:thread_id` 表示本机客户端工作状态，不能据此取得其他会话的权限。原生账号、费用、工具绑定和执行由原适配器控制；不复制另一套任务引擎。

## 接口与顺序

1. 用 `conversation_providers` 和 `conversation_native` 的 list/read 取得实际 provider/thread_id；用户明确新建时才create。历史读取不会发送或续接业务。
2. `assistant_desktop_get(scope)` 读取客户端版本及body；未发送文字最多64KiB，真正原生send仍最多8000 UTF-8字节。当前不支持原生附件/独立模型选择，不能按内置助理的附件提示调用未适配参数。
3. `assistant_native_send(request,revision)`，`request={provider,thread_id,text,request_id}`。provider必须codex/claude-code/gemini-cli，thread_id为原接口允许的1–120位ASCII字母数字/连字符/下划线，request_id为稳定的1–120字节无控制字符编号。不能加入action/cursor/credential_ref、shell或账号参数。
4. 提交先纯查询原服务端回执；已确认的原ACK直接返回，不再调用适配器。没有原回执时先加密原子保存native_pending，再让原适配器执行。旧版本、保存失败或不兼容字段会阻止新提交。原适配器仍按原编号去重。
5. `assistant_native_resolve(scope,request?)`只查询原服务端回执及核对客户端状态，不启动SDK进程、不resume、不send，不调用模型。通常省略request，使用保存的native_pending；客户端响应丢失时可携完全一致的原请求查询。scope必须与request归属匹配。

每个新请求冻结provider、thread_id、text、request_id。它没有新的路由/附件/凭据配置，继承原适配器和原会话的账号/模型绑定；不承诺锁定用户在外部CLI另行修改的隐式全局设置。Codex保留旧回执指纹算法，Claude/Gemini保留完整NativeRequest序列化算法，不迁移历史回执或为了统一改写其哈希。

## 明确区分状态

| 返回 | 含义与操作 |
| --- | --- |
| loaded | 仅仅读到客户端状态；不表示执行 |
| accepted，native_result.state=accepted | 原生消息已受理，使用native_result.turn.id及原会话status/read查询结果；受理不等于任务完成 |
| partial且native_result.state=accepted | 已受理但本机ACK清理未确认；继续查询原请求，不能换编号重做 |
| unknown | 原编号已保留或原服务端有未知回执；不当作完成、取消或未执行 |
| not_found | 尚未查到原回执，不证明原请求已取消；核对依赖后可由用户显式重试完全相同的原请求 |
| failed | 查看code/message，保留原输入；若同时存在native_result，必须核对它，不能把本机保存失败解释为原服务端未执行 |

只有原ACK包含匹配的会话与任务编号才允许清理客户端标记。清理只清空与原请求相同的正文，另一窗口/后续编辑的新稿保留；写盘失败返回partial，ACK仍返回且不能重发。跨窗口正文冲突保留本地输入和原版本，需显式查看/采用已保存版本，不因查到ACK就获得覆盖其他新稿的许可。

桌面重新打开时按原编号查询一次，不执行重试。手动刷新也核对原回执。界面的“重试原请求”使用已保存的原内容；若服务端已存在unknown回执，后端只返回原unknown，仍不再执行。想发送不同内容，先核对原请求或另开会话；更换编号不会自动解决未知状态。

原生会话重新打开时，已受理和运行中都会继续查询原会话状态。即使本机已清理发送回执，也能继续显示进度和最终消息。收到终态后停止轮询。从草稿入口指定原生会话时，直接打开指定会话。整个过程保留当前草稿，只执行状态和历史读取。

首次核对或状态读取失败时仍可编辑草稿，确认原状态后才能发送。只有查到已受理或运行中的轮次才会显示「停止」。状态读取失败时可点「重查原生状态」，该操作只查询当前原生会话的状态。

运行中的状态读取失败后暂停轮询，保留最后确认的历史和当前草稿。重查取得有效的在途状态后继续观察原轮次。状态回包应包含所请求的会话编号，提供方字段存在时也须匹配；未识别状态按待核对处理。应用原生发送回执前，会核对草稿归属、原请求身份及已受理回执的会话编号。任何不一致都保留原草稿和待核对请求。 状态与回执隔离验收

未知回执不得通过采用其他草稿版本清掉。提供存储版本比较和显式采用；坏密文、版本不支持、归属不匹配或原回执读取失败均保持错误，不回退空稿或恢复执行。

## 存储与验证边界

native_pending与body/录音状态保存在同一会话DPAPI密文中；新增字段兼容此前无此字段的文件。索引仅显示待核对摘要，不暴露正文；不使用浏览器存储持久化私人输入。这个契约覆盖原生send，create/interrupt仍使用各自原接口和稳定编号，不将本轮保证扩展为已覆盖所有原生动作。

隔离状态、接口、UI及实际原生/CLI证据写入持续Goal。测试使用合成数据和本机回环模型，不代表真实供应商可用性，也不触碰用户原账号/密钥/会话。

# 原任务继续与后续队列

桌面、CLI和微信共用原任务检查点、保存事务和执行器名额。排队消息尚未开始，不应阻止原暂停任务继续；恢复原任务不自动放开后续队列。其他正在执行或等待确认的轮次仍阻止同会话续接。

微信精确短句（包括“继续吧”“接着做”）按以下规则处理，不让模型猜测执行目标：

| 输入 | 目标与边界 |
| --- | --- |
| `继续` | 当前对话唯一暂停的任务。包括模型受理未知的原任务，但未知情况会被续接入口拒绝，不转而执行队列。多个暂停任务时要求指定原编号；正在处理/等待确认时不替用户批准或放开队列。 |
| `继续 原任务UUID` | 只续接属于当前来源的原任务，沿用其原模型设置、检查点和结果；不会重选其他任务。 |
| `继续排队` | 明确放开当前对话的后续队列，不恢复旧失败任务。 |
| `继续排队 原任务UUID` | 明确放开这个已知原任务所属会话的后续队列，保留最新会话的独立队列。 |

如果当前对话没有暂停目标、也没有进行中的工作，只有暂停的后续队列，短“继续”保留原队列兼容用法。开启新对话后的短“继续”不会隐式回到旧会话。查询/打开页面不视为继续同意。

`assistant_resume` 先读取原 `assistant_turn_get`，核对结构条件；`resumable` 不包含全局实时名额保证。执行入口在修改原状态前检查当前模型开关、原执行器是否退出和全局四个名额。仍在收尾或名额用满时明确拒绝，原状态/队列不变；先核对原状态，稍后再明确继续，不能换编号重新发送。

`assistant_queue_resume` 使用原 `sessionId` 和原会话窗口或完整会话中读到的 `queue_resume_generation`，后者传给 `expectedGeneration`。只有暂停且有待办的会话才公开该值。暂停期间新增或取消排队消息会使旧值失效。旧值、已放开或已无待办时，带版本的请求只返回 `resumed=false` 和当前待办数量。重新核对变化后才可明确继续。旧 CLI 仍兼容只传会话编号。桌面在请求回执丢失后重新读取原会话。控制任务受理后仍按原排队轮次编号查询结果。

控制消息写入的 action、目标和代次不因规则更新而重新解释。重复同一消息或恢复丢失回执只沿用原目标/代次；已保存的旧版本队列回执仍返回旧回执，不再次执行或转而继续其他任务。

新释放只回复已接上后续要求、将按顺序处理，不表示任务完成。原代次已经释放时，丢失回复的恢复只报告核对，不用当前排队条数声称再次执行或启动后来队列。真实图、模拟微信和跨重启证据见队列反馈验收。

模型停用阻止新的队列释放，但允许核对已经提交的旧代次。代次核对和启用检查使用同一个状态事务，旧代次核对不保存会话、不增加状态版本或唤醒队列；通道可单独补存原控制回复。保存失败沿原控制编号核对，不能换编号重发。并发时以实际事务提交顺序为准：停用先提交则拒绝释放，释放先提交后再停用不撤销原受理。专项和限制见模型开关与队列事务验收。

重新启用默认模型会唤醒已受理且未暂停的等待消息，沿用各条原模型快照、请求与附件；改默认路由不改旧队列。明确暂停或重启后暂停的队列仍需明确继续，启用不重启取消/未知/失败任务。调度候选在实际保存前重新核对当前开关、原等待状态、暂停及同会话活动情况，过期候选不写入或改版本。修改其他设置及重复保存启用状态不额外唤醒。边界与实测见队列调度验收。

本轮没有改变存储格式、原容量、默认模型、权限或真实配置。计划和验收记录代码/实际验证状态；源码已更新不表示日常程序已经替换。历史归属不明、模型受理未知及副作用失败保护仍见[恢复说明](assistant-recovery-experience.md)。

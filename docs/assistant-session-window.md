# 会话窗口、完整消息与按需详情

`assistant_session_window_get`是私人只读的会话窗口入口，桌面聊天与交接使用它。旧`assistant_session_get`保留完整兼容返回，不能把新窗口当作整个检查点。

调用`request={session_id:"实际编号",before_message_id:null,limit:40}`读取最近消息。limit为1至40，默认40；单个result实际JSON不超过256KiB。每条messages.content保持完整，预算不足减少实际returned，不用preview代替。page含version=homebase-session-window-v1、captured_revision、total_messages、start_index/end_index及真实before_message_id/has_more。start/end是当前逻辑序列的只读信息，不是授权或可猜测的输入。

需要更早内容时保留原会话编号，使用实际before_message_id；返回该原消息之前的记录，不重复包含它。游标缺失、编号无效/重复、源不可读取及单条超预算均明确失败，不偷偷换会话、跳过或返回截断成功。确实无消息与失败区别。它是一次原子窗口读取，重启后原ID仍可续读；不是另一种历史快照或任务恢复操作。

turns条目包含turn、details_omitted=true、step_count/job_count/artifact_count。turn仅概况：省略原步骤、确认参数、诊断及job正文，最多8项job、16份产物。空字段不证明原始结果为空。原活动/FIFO排队轮次在当前消息页之外也会保留，页面不会因此错误认为任务已经结束；完整详情和审批参数使用原`assistant_turn_get`，界面核对返回的轮次及会话编号，读取失败不展示旧确认参数或执行新操作。

桌面首屏只取一页，读更早内容时再取下一页。活动轮次使用精简进度查询。展开执行详情时，`assistant_turn_inspect` 按原会话和轮次返回状态、审批、产物和 `step_summaries`，清单包含每步的编号、名称和状态。最新进度继续提供当前状态和确认。统一会话中心的交接只读最近最多6条消息，使用独立子缓存，沿用原会话失效通知。

展开某一步才通过 `assistant_turn_step_get` 读取它的参数、任务引用和结果。两个新接口均要求 `private`。桌面核对会话、轮次和步骤编号，独立显示读取失败并支持按原编号重试。折叠时移除正文，同一步在缓存有效时重开可复用。原轮次更新会让相关读取失效，关闭的步骤在下次打开时更新。归档单步读取复用原加密分段。从已校验记录定位步骤并保留原归属检查，只有选中步骤的正文需要复制。 原步骤格式化验收 · 归档单步验收

通过原 assistant_turn_get 传入 includeDetails=false 可读取进度概况。返回 details_omitted=true、step_count、状态、确认、实时输出、产物引用及最多 8 条没有正文的任务摘要。省略 includeDetails 或传 true 读取同一轮次的完整步骤、原任务结果和诊断。冷档案的进度和步骤清单从已校验分段读取任务信息，保留原结果中的未知状态与产物归属。完整正文仍可用原详情接口取回。冷档案进度与清单验收

收到按会话、轮次标识的外部续接事件时，先标记原详情过期，再刷新需要重新定位活动轮次的窗口。新详情仍在读取时，窗口显示已观察到的状态。确认参数以原轮次的当前进度或已核对的清单响应为准。续接刷新验收

后续状态事件在当前读取结束后合并补读一次。离开页面后保留过期标记，重新打开时才查原轮次。已经返回的进度可立即显示。慢读取验收

刷新固定已读取的开头：最新一页因新增消息移动时，只用有界请求补齐原阅读锚点之间的内容，再按原ID和较新captured_revision合并。已读开头不会因“最近N条”滑出，正常查询没有清理记录。翻页保持滚动位置，不把加载更早内容误报成新回复；新回复仍使用已有的低侵入提示。错误保留原范围与输入，不能据此重提业务任务。

CLI结果为partial时应检查page和详情省略标记；分页尚未完成不代表业务仍在运行。窗口只读，不改密钥、配置、消息、任务状态或旧回执。本阶段未实现冷归档、解除容量上限或跨会话模型搜索；内置`homebase_history`固定快照/正文分块约定保持原样。

设计继续采用已核验的固定源码调研中按原session/id读取、保留顺序、将展示与执行证据分开的原则，没有复制参考项目的plaintext存储或引入新框架。

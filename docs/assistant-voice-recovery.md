# 语音输入与原转写恢复

用户主动点击录音，停止后保存至本机私有录音目录，再由固定的本地 Whisper CPU 引擎转写，融合方式固定 manual，不请求云端模型。助理模型关闭时也可以录音、转写和编辑草稿，发送仍需启用模型。草稿、录音回执、原ASR编号和已插入标记放入同一DPAPI桌面状态。

## 使用与状态

活动采集在点击停止前属于未提交录音，离开页面停止麦克风、不启动ASR；这段未提交采集不能承诺跨崩溃恢复。停止后，录音暂存及会话关联须先保存成功，才可提交本地转写。

取消后可立即重新录音。浏览器排队送达的上一段录音停止、错误或权限拒绝，只能影响那次采集；组件核对当前请求和录音器身份后才释放设备。正常停止仍将当前录音交给原转写流程。[W3C MediaRecorder 停止行为](https://w3c.github.io/mediacapture-record/#dom-mediarecorder-stop)

正常在当前页发起的转写完整完成后可插入可编辑草稿，仍不自动发送对话。切换页面或重启后，窗口核对原转写。已有任务编号但执行状态暂未确认时，窗口最多查询三分钟，期间仍可编辑草稿。到期后可手动查询。没有任务编号的未知受理保留手动核对入口。找回结果后先显示预览，用户点击“插入草稿”后才更新正文。原任务失败、部分结果、未识别、容量不足与未知状态分别明确显示。

受控语音入口读取ASR已有任务日志和产物，子进程stdout/stderr不绑定窗口宿主的管道。这样宿主退出不会因日志写入失去读端而使原转写失败，也不会额外把原始stderr写入新日志。旧通用ASR入口仍保留既有事件通道，其耐久进度传输另行完善，不能从语音入口的验收推断其他执行器均可脱离宿主存活。

| phase | 含义与可做操作 |
| --- | --- |
| staged | 录音和回执已保存，尚未越过提交边界；可明确继续转写或取消 |
| submitting | 提交意图已保存，受理仍需核对；重复提交入口只查询 |
| accepted | 已有原ASR回执；查询原任务，不重新启动 |
| unknown | 启动、运行或原记录不能确认；保留原编号/独立目录，只核对 |
| ready | 完整读取到非空、有界转写；可查看并插入 |
| applied | 草稿与已处理标记已原子保存；重复插入幂等，不再重复追加 |
| cancel_requested | 已请求取消，尚不能证明停止；不清回执、不假称取消成功 |
| cancelled / failed | 原任务取消/失败或结果不可用，不插入草稿 |
| dismissed | 用户停止显示；回执保留，不代表取消业务 |

“停止显示（保留回执）”不会停止后台ASR。只有明确点击取消才请求停止原任务；离开页面不调用取消或删除已受理录音。原日志/结果仍在独立目录，便于恢复核对。

## CLI

`assistant_voice_begin(scope,audioBase64,mimeType)` 支持WebM/Ogg/WAV，最多10MiB；成功从 `entry.voices` 取得 recording_id。scope 与桌面草稿相同：new、已有桌面会话UUID，或原生输入命名空间 native:provider:原生ID。原生ID允许1至120位ASCII字母数字、连字符或下划线，与原生适配器的标识约定一致，不假设必须UUID。命名空间不授予原生会话执行权。正文、回执与来源均不写入浏览器存储。

`assistant_voice_submit(scope,recordingId)` 使用单次预检；通过后先持久化 submitting，再允许写原ASR日志和启动本地进程。预检前失败保留 staged，明确重试可修复环境；边界后失败视为未知，不盲重推理或新建ASR任务。raw录音SHA256发生变化拒绝提交。并发调用只有一个能越过准备边界。

`assistant_voice_get(scope,recordingId)` 只对账这份录音的独立输出根和原日志，没有任意文件路径或job编号参数。已保存回执丢失响应时，按原来源目录唯一匹配日志；零个或多个匹配都不自动选择或重提。重启后的旧 running 日志不证明进程仍受本机管理；实际完成还需原任务元数据和文本产物。读取失败不会返回空成功，也不会改写旧ASR记录。

同一录音的状态查询可能乱序返回。已保存的完整文稿、明确失败或已取消状态会保留。迟到的预检错误也无法重新打开已越过的提交边界。用户主动取消或停止显示时，按写入时的实际状态处理。

插入前先保存当前新稿并取得最新 revision，再调用 `assistant_voice_apply(scope,recordingId,revision)`。正文加换行及转写超过64KiB草稿容量或版本冲突时保留转写，不截断覆盖。单份转写仍最多8000字节；插入后正文若超过实际消息8000字节预算，可先保存再编辑，不自动发送。正文和 applied 标记在同一密文文件原子发布，成功后才清理原录音，保留ASR任务和结果。响应丢失先重新读取同一状态；重复 apply 不二次追加。用户以后主动编辑/删除转写文字不触发自动回填。

`assistant_voice_cancel` 只取消本录音原任务；无法确认时保留 cancel_requested。`assistant_voice_dismiss` 保留历史回执，只关闭当前显示。最多512个有界录音回执/输入命名空间，达到维护上限明确拒绝，不静默清历史。`assistant_desktop_index.voice_pending_count` 包含尚未插入/关闭的失败或取消输入，不表示这些任务都在运行。

旧 `assistant_voice_stage/discard` 仍用于兼容：stage仅暂存，不能代替begin的会话回执；不要对待核对任务擅自discard。原生Agent文字输入和原编号受保护保存，发送/查询走 `assistant_native_send/resolve`，详见[原生发送回执](assistant-native-receipts.md)，不能从草稿或录音恢复推断原生任务已经完成。

此子阶段的实现/验收与未完成项继续记录在工作Goal。

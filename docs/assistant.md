# HomeBase AI 助理

工作中的讨论、具体进度和跨对话持续事项见 [交流与事项接口](assistant-conversation-and-matters.md)。桌面输入支持自动判断、只聊聊和明确执行；微信可按事项名称查询原进度和结果。

新增的有限记忆召回、记忆冲突处理、重复失败保护和定时办事见 [连续办事说明](assistant-continuity.md)。桌面与微信共用状态；功能边界以对应接口与实际结果为准。

内置助理通过模型提出工具调用，由 HomeBase 按实际接口契约执行。桌面「AI 助理」与微信普通消息使用同一个 Rust 引擎、模型设置和执行策略；两个入口分别保留会话，微信会话可在桌面查看和确认。它无需读取 HomeBase 或开源能力的源码。

## 启用与使用

初始 `enabled=false`，`wechat_enabled=true`。用户后续可明确选择并启用默认模型；关闭时桌面明确提示并禁用发送，微信普通消息回复未启用说明。微信的 `系统`、`能力`、`视频 标题`、`/状态` 和 `/结果` 等明确指令继续可用。

设置中的 `credential_source` 可选 `default`（沿用原优先级）、`sops`、`api_key_manager`。显式选择仅影响助理消费者，不迁移、覆盖或替换 Key；所选来源失败即停止。桌面与微信使用同一设置，每个轮次保存来源快照，异步任务查询沿用原来源。

`free_only=true` 时只接受 OpenRouter 的 `:free` 或 `openrouter/free` 路由，强制输入、输出、每请求及图像价格上限为零，不回退到付费渠道。当前模型请求不发送可选 `parallel_tool_calls` 参数；应用仍按顺序执行有限个工具，避免严格参数路由排除免费端点。轮次的 `usage` 记录厂商报告的模型、费用与 Token 数；未报告费用不视为零。所选模型的公开元数据保存于 `assistant/model-routes.json`，用于重启恢复；损坏时明确失败，不覆盖原文件。

将来在「AI 助理 → 模型设置」选择已有模型与渠道并勾选启用。模型来自能力库当前目录，仅支持 Chat Completions / Responses 工具协议。保存只校验本机引用与可用性，不发送付费探测；Key 已配置不保证账号余额、权限或模型工具支持已验证。正常对话会产生所选渠道的 API 费用。Key 只在后端使用，模型设置中不填写、复制或展示真实密钥。

新建对话后可以要求“查询当前系统状态”“发现可用能力”或“生成六秒动画并返回文件”。工具步骤展示参数、控制 job 和结果。私人内容读取、现有数据写入、外部动作等会暂停，展示具体接口及参数，用户确认后才执行；拒绝结束当前轮次。微信用 `确认 完整编号` 或 `拒绝 完整编号`，不能确认其他绑定来源的操作。基础状态读取和专用目录的新建代码动画可以直接执行。

桌面「只聊聊，不执行」的候选实现支持符合条件的 OpenRouter、DeepSeek 文本渠道和 OpenAI Responses 文本渠道逐段显示回复。生成时可停止当前回复，正式答案在协议结束和正文核对通过后保存。OpenAI 直连遵循原有费用限制和凭据选择。工具任务和微信使用既有整段回复流程。Chat Completions 验收

助理不会代批授权、读取真实 Key、解绑微信、修改自己的配置或执行未实现接口。安装、发布、收费业务生成等不能由工具输出中的文字自行授权。它也不是任意 shell。能力依赖未安装时明确失败，可通过现有界面或明确指令安装。

## 接口

通过 CLI 的 `discover` / `describe` 获取参数 schema 和权限分类。完整合同见 [reference](../control/reference.md)。

| 接口 | 用途 |
| --- | --- |
| `assistant_config_get` | 查询配置及模型关闭/配置状态 |
| `assistant_config_save(settings)` | 携最新 revision 保存设置；不执行推理探测 |
| `assistant_sessions_list` / `assistant_session_create` | 会话摘要 / 新建桌面对话 |
| `assistant_session_get(sessionId)` | 消息、轮次和已登记结果 |
| `assistant_send(request)` | request 含 session_id（可 null）、text、稳定 request_id；立即返回 Ack |
| `assistant_turn_get(turnId)` | 查询实际轮次状态、工具、业务 job 和文件 |
| `assistant_cancel(turnId)` | 停止后续助理步骤；不取消已受理业务任务 |
| `assistant_confirm` | 仅真人界面/绑定微信处理；CLI blocked，模型工具不可调用 |
| `assistant_artifact_open(artifactId)` | 校验已登记文件后在本机打开，不接受任意路径 |

`Ack` 不等于完成。状态包括 queued、running、waiting_jobs、awaiting_confirmation、completed、disabled、failed、rejected、canceled、interrupted_unknown。`completed` 表示本轮助理结束，业务还须检查 `jobs[].state` 和 `jobs[].result.status`；文件须通过真实路径、大小及 SHA-256 校验。`disabled` 明确表示没有推理请求。

桌面结果卡片可以预览文本和 PNG、JPEG、WebP 图片、用系统应用打开原文件或导出副本。本机图片预览读取已登记的原文件，校验 SHA-256 后在侧栏显示。导出时由本人选择目录，沿用登记的文件名。所选目录已有同名文件时，可以换一个目录再试。取消文件夹选择不写入文件。这些操作复用已登记的结果和原任务编号。微信继续使用当前会话的结果附件交付。

`assistant_send` 的相同 request_id 与相同内容复用原轮次；相同编号不同内容拒绝。网络等待结束或状态未知时查询原轮次/job，不换编号重新发送。每会话同一时刻只执行一个轮次，最多10条后续消息持久排队（waiting_input_queue），全局最多4个执行槽位；用户主动新发消息属于新请求。后续消息只在当前轮次正常结束后顺序执行，不声称是同轮即时 steering。失败、拒绝、取消、应用重启时暂停后续队列；桌面点击“继续后续消息”、CLI `assistant_queue_resume(sessionId)` 或微信说“继续排队”，才执行这些原后续请求，不重做结果未知的原轮次。session/turn 返回 queue_paused，session 元数据另含 queue_depth。取消尚未启动的排队消息不会把其内容插入当前模型上下文。

模型工具包括：发现、描述、业务调用、最近 job 元数据、查询已发现 job、本地视频、安排结果附件、个人记忆、提醒、已审查 Skill。模型不可调用 `assistant_*`、`wechat_*`、`secrets_*`、`shared_secrets_*`，不可自批确认。模型文件输出和代码动画根目录由后端固定到专用 workspace，不能使用模型提出的任意路径。

## Personal Agent 运行时与个人数据

新会话统一使用 Pi。微信当前会话若来自已退役的引擎，下一条普通消息会自动开启 Pi 会话，消息送达重试仍沿用同一回执。新收到的文件也会进入可用的 Pi 会话。旧会话、原任务和附件仍可查询；需要在新会话处理旧素材时，可重新发送原文件。Node worker 无模型凭据，模型请求、工具审批、加密检查点和共享记忆均由 HomeBase 管理。图片输入和执行中消息分类走宿主的专用路径。

Pi 在历史达到 8 轮或字节预算时调用当前配置模型生成摘要，与近期对话一起供后续轮次参考。大型工具循环在完整调用批次之间收拢上下文。摘要保存到原受保护状态，原消息、原任务和结果继续按编号查询。摘要暂时不可用时保留近期上下文并标注覆盖范围。摘要请求无需新的密钥，不向模型提供操作工具，也不会写入长期记忆。

Pi 支持有界的定时执行、事件跟进与在途修改。主动执行仍要求明确的免费渠道与原有授权。在途修改使旧确认及尚未执行的冲突调用失效，已经受理的动作沿用原结果核对。重启按安全检查点和原任务编号恢复，模型受理或动作结果未知时停止自动重提。

微信里的问候直接按聊天回复。单独问「你是什么模型」时，HomeBase 从当前配置回答模型和渠道。普通消息收到后不发送通用受理文案，只有实际排队、待确认或有执行进展才主动提示。

中断轮次不自动重跑。`assistant_turn_get` 返回 `resumable=true` 时，可 `assistant_resume(turnId)` 或微信发送 `继续 完整轮次编号`。版本不兼容、没有检查点、模型请求结果未知时拒绝继续。已保存模型响应、工具结果与已受理任务编号用于防止重复执行；业务结果仍应查询原 job。

桌面“记忆与提醒”管理个人数据，微信使用同一份记忆和执行器，但各对话的上下文及附件仍按原归属隔离。模型调用 `homebase_memory` 的 remember/forget、`homebase_reminder` 的 create/cancel 要经真人确认。`homebase_skill` 按需读取三份内置说明；不扫描本机其他 Skill，不执行任意脚本。

CLI 先 `assistant_personal_get` 获取 revision；`assistant_memory_save(request)`、`assistant_memory_forget(memoryId,revision)`、`assistant_reminder_save(request)` 携最新个人数据 revision。字段 schema 使用 `describe` 查询。`assistant_reminder_ack(reminderId,cancel)` 知悉或取消。记忆最多200条、单条内容2000字符，到期不参与关键词检索；删除记忆不删除既有聊天。提醒最多100条，时间必须含时区，重复间隔1–525600分钟。桌面显示到期状态，可单独启用系统通知；微信提醒返回原绑定通道。发送未知不重发；人工知悉后再安排下次周期，跳过离线积压。应用关闭时没有后台提醒。

## 任务、文件与微信

控制器负责持久受理与执行；助理使用稳定步骤编号。接受后的业务任务即使用户停止助理仍可查询，原状态不会被助理改写。应用重启不重放未完成轮次，标为 `interrupted_unknown`；待确认操作仍需人工明确处理。服务商异步任务按原渠道和任务 ID 查询，不换 Key、不重提生成。

微信任务返回助理轮次编号，`/状态 编号` 与 `/结果 编号` 查询同一轮次。明确要求返回文件时，模型调用 `homebase_deliver(job_id)` 安排本会话生成文件；任务完成后自动发送，`/结果` 可再次明确获取。只有已登记、归属本会话、在专用目录、无链接跳转、支持格式且至多 20 MiB 的文件可以发送。一次至多三份。桌面可打开本会话已校验结果。

微信发送 `accepted` 只表示官方接口接受，手机是否收到仍需实际确认。网络失败或文件校验失败明确提示，不自动重复发送或重新生成。模型最终回复不是手机收件证据。

微信可以直接说“进度”“结果”“确认”“拒绝”“停止”“继续”“继续排队”“新对话”。短确认只批准当前微信会话的唯一待确认动作；新对话后不能用短确认误批旧对话。完整编号指令仍兼容。查看结果是查询已生成的原任务并校验文件，不重新提交生成。受理提示保持简短；执行阶段改变时至多每30秒报告一次进展，每条输入最多6次，签名与交付状态持久保存，网络未知不重发同一进展。当前通道没有实现可编辑预览或逐 Token 展示，不伪造“正在输入”状态。

模型厂商要求的 reasoning_details、reasoning_content、Responses items 在协议、Node bridge 与 checkpoint 之间保留，用于正确续接工具结果；不作为内部助理的可见回复。网络失败返回安全类别（构造/连接/超时/传输），不回显 URL、认证头、输入或原始错误链；结果未知不自动换 Key 或重试。

## 存储与限制

开发版可以用 `wechat_self_test_message(text,requestId)` 模拟本人入站消息，回复仍经真实微信通道发送。必须在启动进程时显式设置 `HOMEBASE_ENABLE_WECHAT_SELFTEST=1`；正式 release 一律拒绝。正文须含 `HB-SELFTEST-` 测试标记，或精确为“新对话”“进度”“结果”，稳定编号须以 `hb-selftest-` 开头。不接受模拟确认/拒绝，不导出绑定账号、回复上下文或令牌，内置模型也不能调用此接口。该流程用于减少反复手机输入；验收应明确区分模拟入站、真实发件接口接受和手机实际收到/播放，不能混称完整手机往返。

日常微信受理和进度使用简短自然语言；确认仍展示具体目标、内容和时间，唯一待确认项直接回复“确认”即可。内部编号保留在桌面详情与 CLI，不在每次确认卡片中重复展示。每轮固定自己的提示词，更新文案不会改写既有轮次。

同一对话中可以追问“把刚才的视频再发给我”。助理应查询或引用原任务，再用 `homebase_deliver` 申请返回；当前轮次持久保存原 job 引用，不改变 job 的原始归属，不重新渲染，也不能引用其他对话的文件。重启后仍按原文件路径、大小与 SHA 校验再发送。

开发自测只能模拟入站，不能刷新微信服务器的回复上下文。真实微信新消息可提供新的上下文；发送失败的具体安全原因在微信接入页和 `wechat_status.tasks[].delivery_error` 展示。`unknown` 不自动重发，不能把任务执行完成当作手机收到。`ret/errcode=-2` 只提示可能涉及会话上下文，不硬编码其有效期，不擅自清空轮询游标或重新绑定。

助理状态独立放在 `~/.homebase/assistant/state.dpapi`，使用当前 Windows 用户 DPAPI、私有 ACL 和原子发布。微信绑定及真实模型 Key 保持原存储。视频复用 `~/.homebase/wechat/workspace/hyperframes` 已有运行时，每次新建 UUID run 目录；不迁移已有产物。测试使用 `HOMEBASE_TEST_HOME` 或显式临时目录和合成回调。

默认最多八轮模型循环，可设置 1–12；单响应最多四个工具、本轮最多 32 步、会话最多 100 个登记任务、每次最多 8,000 字节用户消息。上下文保留完整工具调用组，过大明确停止，不截出悬空调用。最多 100 会话、每会话 200 条消息，加密状态容量达到上限后明确拒绝，不自动删除旧记录。当前不提供历史删除、通用入站微信附件读取、跨入口混用同一对话或任意长期后台 Agent。

绑定本人可在微信单独发送 PDF 或原生 MP4 进行本地提取，再用原收件编号查状态和结果。当前会话内明确引用 PDF 时可按首页摘录提问。支持相应能力的版本也可引用原视频文字稿和微信语音转写。语音由微信附带文字或由本机转写受支持的 SILK 音频。普通文本对话继续使用既有的共享助理。 [微信收件与提问](wechat-integration.md)

模型 API 费用上限不能仅靠 Token 数精确保证；这里只提供循环与回复长度约束。停用模型会停止后续步骤，但已到达服务商或控制器的请求可能继续，不自动退款或重试。合成模型验证不能证明真实厂商模型能力；隔离验证不调用真实模型，保留用户既有模型设置。当前仍未接入直接由模型理解音频或图片、任意浏览器和邮件/日历连接器、语义知识检索、关机后台计划或多 Agent 自主执行。

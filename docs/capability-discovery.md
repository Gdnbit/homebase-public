# 按功能发现与比较能力

桌面卡片、助理工具桥和CLI复用现有模型、服务、仓库、MCP、Skill及本机能力的派生索引。没有新增配置源或复制密钥。发现只读元数据；账号、运行包、连接、成本和权限仍在实际执行前核对。

可选`pricing`按具体模型渠道保留参考单价和采集时间；可选`provenance`区分仓库登记、记录一致性和执行前代码检查。价格、摘要及标识不因分页裁剪，无效归属明确进入来源错误。零报价不是免费或授权；列表不扫描全部安装文件。字段、单位、缺失维度及原结果校验见[费用与验收依据](capability-facts.md)。

## 查询流程

先执行`hb describe capability_index_query`，读取自包含输入/输出Schema；调用需要`--allow-private`。顶层参数为`request`，内部字段使用snake_case。

```json
{"request":{"query":"视频","offset":0,"limit":10}}
```

首次请求不提供`catalog_id/snapshot_id`，从现有来源读取一次目录。返回：

- `catalog_id`：固定的源目录身份；5分钟内另换query/function/kind时复用，避免重扫来源。
- `snapshot_id`：本次筛选视图身份；续页必须携带它、相同筛选和原`next_offset`。不要用limit猜下一页，因为实际JSON预算可能使本页少于limit。
- `total/groups`：同一筛选的完整条数与功能分组数量，不只统计本页。分组过多时`groups_has_more=true`，可进一步按实际function筛选。
- `source_complete/issues/issues_total/issues_has_more`：来源完整性与省略边界。来源失败不等于空库；单个坏条目不会清空其他正常来源。
- `entries`：实现引用、来源类型、状态、费用类别、发现接口、前置条件及证据说明。`summary_truncated=true`表示说明被缩略，标识和target不会裁剪；运行前按原discover/describe读取完整契约。

继续同一筛选：

```json
{"request":{"snapshot_id":"替换为原snapshot_id","query":"视频","offset":10,"limit":10}}
```

示例中的10只是结构演示，实际offset必须取返回的`next_offset`。当它为null时该视图读完；没有运行中的执行任务。CLI对还有下一页、来源不完整或说明省略返回`result_state=partial`并给出具体提示。

从同一源目录按其他功能筛选：

```json
{"request":{"catalog_id":"替换为原catalog_id","function":"document","offset":0,"limit":10}}
```

query最多240 UTF-8字节、不含控制字符；limit为1..40，缺省20。function使用实际目录标识；kind为model/service/repository/local/mcp/skill。可以按名称、来源、功能别名和目标引用搜索。已安装 Skill、已登记仓库和已配置 MCP 的简短用途描述也参与匹配，适合从自然语言需求中提取短关键词；能力目录只返回原条目，具体工作流和工具参数仍按原接口读取。发现 MCP 时只读取配置，实际调用前仍须核对服务器授权和工具契约。

统一目录和本机能力设置共用 MCP 的只读检查。服务器地址、启动参数或认证字段变化后，曾经授权的同编号连接会显示待授权。已匹配授权但缺运行变量或凭据引用时显示尚未配置。明文认证字段、禁止助理使用的服务器和本机工具停用各有明确提示。已授权的条目仍显示连接待核对。目录查询不解析凭据值，不启动 MCP 或访问其地址。若本机目录无法读取，其他来源仍可用，响应会说明 MCP 来源不完整。 [MCP 工具发现与调用规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

已有选中项时，将原条目的 `entry_key` 放入 `request.entry_keys`。需要 1 至 3 个互不重复的 64 位小写十六进制标识，条目按所请求的顺序返回。可以叠加 `function`、`kind` 或 `query`。响应的 `unmatched_entry_keys` 覆盖整个筛选视图，和本页 `limit` 无关。它表示当前视图内没有匹配，可能是实现已移除、被其他筛选排除，或来源未能读全。来源不完整时应说明仍待核对。普通浏览省略该响应字段。 [JSON Schema 数组约束](https://json-schema.org/understanding-json-schema/reference/array#uniqueness)

比较草稿中的两个标识可按下面结构一次提交。请替换所有占位值。续页保留 `entry_keys` 的顺序。

```json
{"request":{"catalog_id":"<原目录编号>","function":"<原功能标识>","entry_keys":["<第一项原entry_key>","<第二项原entry_key>"]}}
```

每页JSON最大9000字节，含中文、emoji和转义。内存源目录最多4个、总32MiB，单目录最多16MiB/50000条，视图最多32个，5分钟过期；淘汰或过期明确报错。`DISCOVERY_FILTER_MISMATCH`不会混合两个筛选，`DISCOVERY_SNAPSHOT_EXPIRED`不会偷偷扫新目录；显式重新从offset=0发现即可。应用重启不保留派生快照，原能力配置和执行结果不受影响。

旧`capability_index_get`保留兼容，返回相同元数据的全量索引；大目录的AI调用应使用分页接口。

助理执行器按动作副作用去重，不把显式只读查询当成写入回执缓存。用户明确再次发现最新目录时会取得新快照；同一写入的重复调用仍复用原结果。网络重传同一请求编号仍按原控制账本核对，不借刷新更换编号重做写入。

CLI/AI控制层保留固定的`DISCOVERY_*`错误码及公开处理提示，不原样传出底层路径、参数或错误正文；桌面与CLI可以一致识别过期、筛选不符和容量边界。

## 选择与执行

功能分组不意味着实现等价。模型route_id决定原凭据引用；Skill是工作流，MCP是工具来源，仓库按原注册验收与输入契约运行。`unknown`费用不能按免费，`local_compute`表示本机资源消耗，`depends_on_tools`表示依赖具体工具。发现时不探测服务商或发起付费请求。

已安装 Skill 和助理的本机 Skill 工具复用同一目录。来源包括共享目录、Codex、Agents、Claude 和 OpenClaw。按显示名或安装名找到条目后，把完整 `target` 作为 `homebase_installed_skill` 的 `read.id`。如记忆用的是另一个安装别名，可用该工具的 `list.query` 搜索，再读取返回的主编号。同一文件夹的多个安装链接合并为一条。目录只展示元数据，真正的说明和资源按任务读取。来源异常会报告该来源不完整，其他条目仍可使用。 [Agent Skills 规范](https://github.com/agentskills/agentskills/blob/main/docs/specification.mdx)

`verified`等状态只表示原注册表的验收信息，不是新执行证据；模型目录`not_verified`明确表示账号调用权限未验证。每个条目的`prerequisites/evidence`说明应如何核对，不能当作新用户授权。

PDF文字提取作为文档本机实现列出：桌面/CLI显式导入与提取，内置助理仅可读取本轮已正式提交的引用。微信和原生Agent附件、OCR、图像理解尚未接入；目录不会假称已支持。

桌面功能卡片统计整个筛选，抽屉只在打开时懒读取实现并按需续页。固定目录的筛选/分页内容持续复用，不因普通查询的分钟过期计时重读；搜索复用源目录。手动刷新或来源变更读取新目录，当前抽屉按新ID更新；打开已过期目录时先读取新目录。过期续页保留已显示内容并给出明确刷新入口；选择实现只准备可编辑草稿，不提前执行。查询缓存仅在内存，不保存Key。

### 选择到助理的资料交接

「使用这个实现准备任务」和「让助理按任务选择」仍只保存独立草稿。顶部保留可补充的“我的任务”，后附`homebase-capability-selection-v1` JSON资料：原catalog引用/采集与到期时间/来源完整性、功能以及所选实现的kind、provider、target、entry_key、原状态、费用类别、公开凭据引用说明、前置条件、精确报价和验收范围。泛功能选择的implementation为null，不凭空指定实现。没有目录或功能不匹配时明确拒绝准备。

名称、discover与其他来源文字都在JSON资料中，不构成新的任务或授权。交接不是接口调用示例，AI须按实际describe/resolve填写参数；有效catalog可复用，过期时明确重新发现并核对原实现，不能混合新旧版本或把未知费用当免费。只复制公开契约字段，不展开额外属性；超8000 UTF-8字节不截断标识或报价、不创建部分草稿。该边界仅为来源和权限组织，不承诺大模型永远不受提示注入影响，实际执行仍由原后端策略和具体授权校验。

目录/功能/实现身份作为现有交接contextKey；刷新后的旧响应不改变当前选择或自动跳转，旧受保护草稿仍保留。没有新增能力配置源、凭据副本或执行接口。具体实施和验收范围见交接计划。

### 配置、账号权限和目录来源分别核对

模型条目的state仍是原account_state，不能用本机已配置/已阻断替代账号推理权限。credential_binding为原目录中唯一provider匹配的默认公开凭据引用；prerequisites另保留默认配置状态、来源、远端状态、到期警告及目录同步说明。缺失、空引用或重复匹配明确为未知，不选择第一条、不换凭据。这个默认视图不覆盖调用者显式选择的credential_source，执行仍须model_capability_resolve核对本次请求。

到期警告不等于block策略；已同步也不等于账号可用或费用为零。同步失败保留原目录并说明来源错误，不把模型当作不存在。公开摘要超过预算时沿用summary_truncated提示，完整内容按原目录查询。

服务条目带原用途说明、状态和凭据引用；统一页明确显示已到期、已阻断、已关联等已知状态。configured只表示配置事实，服务适配器是否开放仍要查实际接口，不能据此调用或自动发布。运行条件可展开查看，选择后同一资料进入受保护草稿。没有新增wire字段或执行能力，详见状态补齐方案。

原服务目录的invalid配置/坏日期与unknown状态也分别保留；只有空/缺失才标not_configured。未知状态或自相矛盾的配置元数据不能解释为用户没填，坏日期不能伪装为一个已知到期时间。这些说明不改变原生命周期执行策略。

## AI契约与验证边界

助理的`homebase_discover`找到查询入口，`homebase_describe`返回自包含输入/输出Schema及前置条件；共享定义按真实引用递归附入，不让AI去源码寻找类型。当前全部开放模型接口的契约均检查不超过9000字节；未来超出时明确报错，不输出损坏JSON或缺失引用。

设计来源与取舍见实施方案。本阶段使用合成目录、实际Deep Agents图、自动模拟微信和隔离原生程序验证；真实厂商可调用性仍取决于原账号/模型适配，不能由目录或合成模型结果推断。

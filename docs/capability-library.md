# GitHub 项目能力库

## 当前范围与事实源

能力库入口为 `/capabilities`。新增 GitHub 自动接入区提供公开仓库分析、固定发布包安装、stdin/stdout接口封装、隔离行为验收和注册；桌面与微信共用发现/调用接口。当前驱动支持单一 npm CLI，首例为 Marked 文本转换。完整边界、调用和恢复见 [GitHub 仓库能力接入](github-capability-pipeline.md)。保留固定 `hyperframes.animation` 视频适配器及原草稿区。

草稿的唯一持久化来源是当前 HomeBase WebView 本地存储 `homebase.capabilities.drafts.v1`，格式为 `{ version: 1, entries: CapabilityDraft[] }`；不属于原生能力注册表，不供 CLI 自动执行。重进页面读取本地事实，打开编辑不产生后端查询。读取失败或损坏时禁止新增覆盖，显示错误与重试；写入失败保留表单。保存时比较打开编辑时的原始版本，发生外部修改需重新读取并核对后重试。

普通草稿仍是“待封装与验证”，不自动变为可执行代码。新增接入区需实际通过固定来源、隔离执行及明确样例后才注册；不会直接执行草稿命令或把自然语言说明当作 schema。原草稿不迁移、不覆盖。复制的任务说明只引用用户保存的草稿，不读取密钥或用户其他配置。

## 开发

新增“按功能发现 → 开发”，复用本机Agent Autoloop的可执行工作流，支持参数表单、稳定请求、任务查询、问题回答与宿主验收。它是专用适配器，不通过通用npm文本CLI安装流程。使用和边界见[开发能力](development-capability.md)。

## 首个实际能力：HyperFrames

来源为 [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)，Apache-2.0，固定 npm 版本 0.9.26，并核对 npm 包 integrity。项目由 AI 编写 HTML 动画、由本机 Chrome 和 FFmpeg 渲染 MP4，不是扩散模型文生视频。当前适配器使用代码内的确定性动画模板，CLI 输入标题、副标题和 2–12 秒整数时长，输出 960×540、24fps、无声 MP4；不需要 HeyGen、OpenAI 或其他服务商密钥。

安装只接受新的空目录或带有本模块所有权标记的目录，拒绝根目录、网络共享和目录联接；不覆盖已有业务目录。npm 依赖与锁文件、缓存、临时用户目录、工具和结果均在指定目录。npm 安装禁用生命周期脚本和用户 npm 配置；运行子进程使用系统项白名单环境，不继承凭据变量。使用系统 Chrome 的可执行文件，但使用独立临时配置；关闭上游遥测和更新检查。FFmpeg 从项目自带工具复制，ffprobe 从固定 npm 包安装。

`capabilities_catalog` 返回实际状态及机器可读输入输出要求。安装完成只显示 installed；只有真实渲染通过尺寸、帧数、时长、完整解码检查并保存结果后，才显示 verified。结果读取重新核对文件哈希，文件变化明确失败。安装与生成按目录串行，操作锁不会被查询自动删除；目录和结果均不自动清理。

四个实际接口：

| 接口 | 参数 | CLI 权限 |
| --- | --- | --- |
| `capabilities_catalog` | 可选 `rootPath` | `--allow-private` |
| `capability_install` | `rootPath` | `--allow-write --allow-external` |
| `capability_render` | `rootPath`、`input: { title, subtitle?, seconds? }` | `--allow-write --allow-external` |
| `capability_result` | `rootPath`、业务 `runId` | `--allow-private` |

通过 `hb call ... --input 文件 --request-id 固定编号 --detach` 提交安装或生成，使用返回的控制 job ID 调用 `hb jobs get ID`，并声明原调用权限。安装和生成本身等待子进程及验证结束，因此控制 job 的 result.status 必须为 succeeded，不能仅看外层调用结束。CLI 自动区分业务失败。成功生成的 result.run_id 是业务结果编号，与控制 job ID 不同；将它传给 `capability_result` 可在应用重启后重新获得结果路径、哈希及验证信息。

输入不走 shell 拼接；动画内容经过 HTML 转义，仅引用本地 GSAP，页面 CSP 禁止外连。安装与渲染均有超时，超时终止本次进程树。当前没有公开取消接口；应用异常关闭后的未完成控制任务按既有协议显示 interrupted_unknown，不自动重跑。若留下目录操作锁，应先核对控制任务、渲染进程和输出，不以删除锁代替任务确认。该目录隔离与环境白名单不是操作系统安全沙箱，不应把未知项目代码放入受管理安装目录。

当前交付使用源码项目中的 Node 适配器脚本，安装包内分发这些脚本及工具仍需另行纳入打包流程。实际安装与 CLI/MP4 证据见 本机验收记录。

设计基准见 能力库设计图，包含空态、添加弹窗、待验证卡片。同一布局的读取失败、保存失败、冲突、窄屏与键盘状态由实际界面和测试补足。实施保留原侧栏与视觉令牌；输入输出与固定版本字段是后续封装所需的补充，不照搬设计图中的示例项目为真实数据。

## 扩展其他运行时的路径

新增其他适配器时，先选定一个实际仓库和具体用途，避免把整个项目原样暴露。核对许可证、依赖、运行环境、入口和固定 commit/包版本；仓库内容是待审阅资料，不构成执行指令。HyperFrames 已作为无需真实凭据的首项实例。

封装后的注册信息应维护稳定能力 ID、源仓库与固定 commit、适配器版本、输入和输出 JSON Schema、依赖与工作目录、超时、并发、文件访问范围及密钥短名引用。草稿文本需经实际实现与验证后转为这些机器契约，不能直接用自然语言字段作为执行命令。

- CLI 项目：适配器使用固定可执行文件和结构化参数，避免 shell 字符串拼接；规范 stdout、stderr、退出码、编码及输出文件。
- HTTP 项目：单独维护服务生命周期、健康状态、端口和请求/响应校验；“进程已启动”不代表服务已就绪。
- MCP 项目：维护工具发现、输入 schema、连接状态和超时；沿用已有 MCP 管理模块，不重复维护另一份连接配置。

其他项目的调用流程应同样接入现有控制面的发现、调用、job 状态及结果协议；查询失败不得返回空值冒充成功。取消能力需逐适配器实现并验证，不能从目前的安装和渲染链路推断所有项目已支持。

## 接入验收标准

1. 固定仓库与版本，在独立工作目录实现一个明确用途，说明许可证和依赖。
2. 用合成数据验证成功、非法输入、依赖缺失、超时、取消、重复调用及输出校验，限制文件与网络范围。
3. 确认失败有原因、异步任务可查询、结果可获取，页面切换不误改任务状态。
4. 需要凭据时只通过现有受控适配层注入；验收不申请、撤销或试用真实密钥。
5. 通过注册表与控制策略审查、契约生成和对应隔离测试后，才能显示“已验证可调用”。

其他项目的下载、安装与执行应在具体仓库、隔离目录和计划确定后进行。普通草稿区不会自动触发这些操作。

# HomeBase 维护迭代 Goal

用一个可验收的迭代周期推进 HomeBase。每轮从已核对的提交开始，记录要改善的用户场景、复现方法、范围和完成条件。把结果保存为独立的本地提交，方便回顾和合并。

## 迭代顺序

1. **可运行性**。从干净检出核对 Node 和 Rust 锁文件、前端构建和原生自检。Windows 打包单独校验所需运行时和产物，旧有效安装包保留到新构建通过关键步骤。
2. **助理主流程**。桌面和模拟微信复用 Pi。用合成消息检查连续聊天、能力发现与调用、任务查询、重启恢复、附件交付。每个测试核对原会话或任务编号，并统计执行和回复次数。
3. **性能与仓库整理**。从页面切换、手动刷新、任务完成更新、能力查询或 CLI 轮询中选出能稳定复现的问题。用请求次数、读取字节或同条件耗时记录改动前后。只处理无运行引用、可重建或已退役的文件，给仍有历史用途的材料保留可恢复的位置。

## 自动验证

- 前端用 `npm run build`、`npm run lint` 和受影响的 Playwright 用例。用测试夹具计数，验证刷新、缓存和重复请求。
- CLI 用 `npm run control:check`、`npm run test:control:contract` 和隔离控制服务。保留原任务号，验证脚本始终查询原结果。
- 原生改动用 `cargo check --locked --manifest-path src-tauri/Cargo.toml --all-targets` 和相关 Rust 测试。模拟微信、测试模型和测试目录都使用合成数据。
- 遇到外部依赖或权限问题，记录缺失的条件和受影响的验收，先做可以独立完成的部分。真实凭据、用户配置和日用数据使用现有入口管理，自动测试使用隔离目录。

## 按用户场景验收

| 场景 | 通过条件 |
| --- | --- |
| 桌面会话与模拟微信 | 连续消息进入对应会话。重复消息沿用原轮次，查询、重启和交付不会重做已确认的动作。 |
| 能力库与 CLI | 从功能找到对应实现和输入契约。调用后可通过原任务编号得到业务状态与产物，缺少依赖和结果时有明确原因。 |
| 模型、连接和密钥 | 验证引用解析、关闭和读取失败。使用合成凭据检查到期、轮换、恢复及重试。 |
| 页面与后台数据 | 导航、手动刷新与任务完成事件只触发所需读取。读取失败时可核对上次成功结果和更新状态。 |

Windows 历史会话在写入时间稳定至少两秒后复用摘要。验证同长度文件快速覆盖后不会返回旧摘要，同时验证稳定文件可供多次列表查询共用一次正文解析。

测试分层参考 [OpenClaw 测试指南](https://docs.openclaw.ai/help/testing)，任务重试参考 [Temporal 活动幂等性](https://docs.temporal.io/activity-definition)，执行状态与就绪检查参考 [n8n 队列模式](https://docs.n8n.io/hosting/scaling/queue-mode/)。

一轮完成时汇报提交、验证覆盖、性能前后对比、清理及恢复位置，以及仍未覆盖的场景。下一轮优先从上一次未覆盖的实用场景和新出现的可复现问题中取任务。

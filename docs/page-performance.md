# 页面性能约定

应用按路由加载代码，侧栏、全局到期提醒和授权弹窗始终挂载。知识库的 Wiki 与逻辑图分别按需加载。普通路由离页后卸载，复用查询缓存。投料和文章编辑器保留草稿与原任务监听，收起时暂停页面轮询，发送快捷键只在编辑器可见时生效。

当前首页为AI助理，硬件概况位于工作台；历史时间线、文章、投料和快捷面板从设置的已有工作入口进入。共享MCP/Skill位于能力库的工具与工作流，未打开前不读取；外部AI启动说明位于设置的高级集成，打开组件后才查询。下表的旧功能名称指其保留页面，不代表仍是首页或常驻侧栏。

## 查询策略

`src/lib/query-client.ts` 创建生产 QueryClient。缓存只在内存中，不写 localStorage、SQLite 或磁盘。相同 queryKey 共用结果和进行中的请求；参数、目录和文档标识必须进入 key。

| 数据 | 新鲜期 / 更新方式 |
|---|---|
| 默认元数据 | 30 秒；再次挂载时过期才读取 |
| Agent 配置与历史、知识目录、拓扑、共享配置、治理静态清单、模型整机概况 | 60 秒 |
| 系统基本信息 | 5 分钟；与模型推荐共用底层查询 |
| CPU / RAM、GPU、Agent 状态 | 分别 5 秒、10 秒、3 秒新鲜期；可见页面继续按原周期轮询 |
| Agent 版本 | 原有 1 小时新鲜期；缓存也保留 1 小时 |
| 密钥到期状态 | 保留每分钟轮询和窗口回到前台复检；前端时钟更新提醒文案 |
| 生图进度 | 相同查询键共享请求；仅未完成的工具卡启用 1 秒轮询 |
| 图片附件 | 相同输出路径共用读取；不再使用后 1 分钟回收缓存 |

普通查询无额外自动重试，错误保持错误态；页面已有的轮询、人工重试及启动自检有限次复检仍有效。缓存失效不等于后台自动全量扫描：只有当前活跃查询立即重读，未打开的视图在下次访问时重读。

除版本与附件等特殊规则外，未使用缓存 10 分钟回收。页面仍挂载的数据不会因为此计时被清除；大文件正文不能据此视为无限容量缓存。

## 各页面及子功能检查

| 页面 | 处理与保留的机制 |
|---|---|
| 工作台（原概览） | 磁盘 / 硬件与 System、模型页复用 key；仅挂载时轮询；保留失败/未知提示 |
| Agent 管理 | 5 个状态查询共用后端 1 秒 PID 快照；配置元数据仍实时检查；模型、历史抽屉按需查询；版本、ACL 复用缓存 |
| 能力库工具与工作流 | 共享 MCP、Skills 仅打开相应页签后挂载，复用原查询缓存；手动刷新只失效对应数据，不扫描未打开功能 |
| 历史对话 | 往返页面复用结果；详情与代理抽屉共用会话 key；首次渲染 100 条，按需加载更多；搜索覆盖全部记录并使用 deferred value |
| 文章生成 | 会话列表原有每 30 秒刷新；生图卡共用进度查询；附件同路径去重；Markdown 正文不变时跳过重新解析；可见时更新计时 |
| 快捷面板 | 三处整机信息消费者共用 QueryClient；硬件查询与概览/System 共用；模型/ASR 恢复和历史读取合并开发 StrictMode 同时请求 |
| 模型下载 / ASR | 采用完成后再等待的串行轮询；隐藏窗口暂停，返回前台恢复；卸载后不回填；完成事件与补偿轮询均刷新模型清单；查询失败明确提示未知 |
| 投料口 | 保留事件驱动的提交/任务完成失效；运行计时隐藏暂停；事件摘要只在事件变化时重新解析 |
| 知识库 | Wiki / AI 子页与逻辑图分别延迟加载；逻辑图不额外读列表或 Obsidian health；子目录仍仅展开时读取；新增“刷新知识库”用于外部修改后主动失效 |
| 密钥 | 保留保存/轮换后的 list 与 lifecycle 失效、冲突检查和后台权限；前端缓存不用于写入授权；没有缓存解密值或增加解密调用 |
| 治理追溯 | 静态清单 60 秒缓存；审计与快照保持 30 秒；保留人工刷新和操作后刷新 |
| 系统 | 与概览共用磁盘查询；PATH、进程与 GDNbit 保留各自刷新周期/人工复检；不全局轮询未打开页面 |
| 全局入口 | AI 接管弹窗关闭时不查询；启动自检缓存及有限次重试不变；IPC 就绪后轮询从 10 秒降到 60 秒，未就绪时仍 10 秒 |
| AI 助理 | 本机能力、记忆与提醒面板首次打开时才载入组件。发送、核对原回执、新建或停止后刷新相关会话，按需再读该轮状态。顶部手动刷新仍可更新助理配置和已打开的信息。 |
| 能力库 | 默认按功能页只载入必要组件。模型与服务、仓库、工具与工作流切换后才载入各自代码。已生成的目录按原目录编号筛选和分页。 |
| 微信连接 | 扫码确认、到期或结束后停止二维码轮询，界面仍可关闭或重新扫码。无绑定且未扫码时每 30 秒核对，连接状态每 5 秒核对。手动刷新复用同一查询。 |

## 更新正确性与边界

- 历史页和代理历史子页手动刷新时，同时失效对应的会话详情；重新打开详情不能继续使用刷新前的正文。
- 模型/ASR 完成事件清除活动任务标识；迟到的补偿轮询仅在标识仍匹配时回填，避免完成状态退回 running 或重复读取结果。
- Studio 的事件订阅只依赖稳定的 QueryClient；回复持久化结束后才失效会话列表，保存失败保持可见提示。
- Wiki 消化完成同时失效知识列表与文档缓存；Wiki AI 优化完成会更新已打开的预览。终态事件在 effect 中处理一次，查询失效不放入 React state updater。
- 治理页面手动刷新期间禁用刷新按钮，并复用未完成请求；共享凭据状态复检等 IPC 请求全部结束才允许再次点击。
- 写入成功后须 `setQueryData` 或 invalidate 对应 key。保存、轮换、到期权限判断仍由后端的当前数据决定，不能用 UI 缓存绕过。
- 构建新能力索引时独立读取模型、仓库和助理状态。模型在一次快照里合并，仓库以一个只读进程提取已登记的公开字段。原有公开分页和执行前核验保持原语义，读取失败继续标为来源不完整。
- 模型整机概况刷新会重新读取 manifest，同时复用仍在新鲜期内的硬件数据；硬件设备热变更可能在 5 分钟新鲜期内尚未体现在静态系统信息里，动态 GPU 与指标按自己的周期更新。
- 外部编辑文件不会自动触发每个页面全量重扫。知识库可手工刷新；其他配置使用已有刷新入口或离开后过期重进。
- Agent 快照只保存匹配 PID，最多延后约 1 秒观察进程变化；不保存命令行、配置正文，也不缓存扫描失败。进程扫描移到 blocking worker，避免阻塞 async executor。
- 不使用浏览器后台任务来停止实际下载/转写；暂停的只是查询和显示时钟，后端任务继续执行。
- React Query 不取消已经送到 Tauri 的原生命令；卸载会停止后续轮询，手写轮询的迟到结果被丢弃。
- 生图卡沿用“最新进度记录”选择规则；此次不改写多任务配对协议。附件假设生成结果使用不同输出路径；图片若被外部原地覆盖，需等待未使用缓存回收后重新打开，或重启应用；不会主动监听图片文件覆盖。

## 读写开销

- 助理根据当前会话建立轮次索引。消息正文保持不变时，输入或实时进度更新可以复用已解析的历史任务资料。知识库在无筛选时直接使用全部文档的分组。
- 模型目录只缓存合并后的公开模型元数据。同步成功或更新固定路由后清除合并结果，分页只复制当前页。凭据状态和失败信息仍按原接口读取，调用时继续核对权限和费用。仓库搜索每条记录编码一次，支持原来的多词匹配、顺序与分页。
- 治理审计和 Studio 列表逐行核对 JSONL。前者只保留请求的最近事件，后者只保留标题、时间与条数。大文件读取在阻塞工作线程执行。坏记录仍明确报错，读取不修改源文件。
- 任务事件日志复用每条记录已编码的字节数和总计。记录淘汰时直接扣除原大小，保留原有容量、脱敏和序号规则。

## 隔离验证入口

```powershell
npm run build
npm run lint
npm exec playwright test -- --config playwright.ai-control.config.ts
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib performance_pid_snapshot -- --test-threads=1
npm run test:control
```

浏览器性能夹具拦截所有 Tauri 调用，外部网络被阻止；PID 快照测试注入合成扫描函数。没有对真实业务数据、密钥或付费服务进行性能压测。结果见 `page-performance-validation-2026-11-09.md`。

页面切换、人工刷新及任务完成后的后续验收见 刷新回归记录。

任务恢复已经改为只读观察，页面挂载、切换和重查均不改写状态；新挂载重读当前观察，StrictMode 并发请求仍合并。当前实例未托管的历史任务显示未知并保留原记录。详见 [任务恢复约定](quick-panel-task-recovery.md)。

运行信息查询也与初始化分开：`distribution_info` 只解析现有路径、检查文件及有界读取初始化记录，不再同步随包AIHub或重写状态。初始化时间取真实记录，未知同时给出状态和警告，不能以当前时间伪装。旧程序资源覆盖的实际复现与新版连续只读验收见本机更新记录。
# 知识索引状态补充（2026-11-17）

AI知识库默认逻辑图仍按需加载，未打开列表不读取`docs_list`。未查询状态显示“切换到列表读取文档”，不能用0篇代替；读取中、明确失败、成功空列表及成功数量分别呈现。刷新失败时保留已有列表并标出读取失败，手动刷新成功后更新计数。健康查询失败显示状态未知，不持续显示加载中。相关调用次数与刷新恢复回归位于`performance.spec.ts`。

助理的手动刷新会合并快速重复点击，并复用正在读取的本机查询。读取完成后可以再次刷新，任务完成事件仍会核对原会话和结果。

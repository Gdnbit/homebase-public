# ASR 实现与历史验证记录

这里整理早期 ASR 验收的技术内容。当前目标机的引擎和账号就绪情况由运行时检查。 [ASR 工作台](asr-workbench-integration.md)

## 已建立的验证边界

- 任务入口先做运行时、目录、模型和配置预检。
- 推荐根据 CPU、GPU、显存、模型完整性和磁盘条件给出状态及原因。显卡选择区分物理 GPU 和虚拟显示适配器，显存用统一单位展示。
- 结果工作区展示引擎原始产物、对照、整理结果和任务状态。导航和重启后可以沿原任务查看。
- 人工整理与模型整理走可辨认的执行方式。输出检查按任务目录和允许读入的文件范围进行。
- 可移植配置导入后用目标机重新检查目录及依赖。

## 历史桌面验证

当时在 Windows 桌面检查了显卡识别、显存单位、模型清单、查看推荐时的硬件状态及最小桌面宽度。机器规格和 CPU 转写耗时参照见 [多引擎设计](asr-multi-engine-design.md#历史测试机与一条性能参照)。

## 复验入口

- `npm run test:asr` 检查推荐边界和可移植配置。
- `npm run test:preflight` 检查 Tauri 版本及自检界面错误和复检。
- `npm run build` 验证 TypeScript 和前端产物。
- 用短合成音频确认一次完整任务，另测取消、读失败、原编号查询和进程中断。

真实模型权重、费用、服务商账号和设备接入按实际目标环境验证。 [可执行验收条件](specs/asr-control-plane/acceptance.md)

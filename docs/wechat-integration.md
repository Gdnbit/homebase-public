# 微信接入 HomeBase

通过腾讯官方 iLink 协议绑定本人微信。普通消息默认交给与桌面共用的 [AI 助理](assistant.md)，明确指令继续兼容。助理初始化默认关闭，启用后使用同一模型、明确的凭据来源与免费策略；实时状态以 assistant_config_get 为准。“系统”“能力”“视频 标题”等指令仍可直接使用。系统不执行任意终端命令。

## 绑定与运行

1. 启动最新版 HomeBase，打开侧栏「微信接入」，点击「扫码绑定」。已授权的 AI 也可用 `wechat_login_begin` 发起，但不能读取二维码内容。
2. 使用本人微信扫码，在手机确认。若微信要求配对码，在 HomeBase 弹窗输入手机显示的数字；不要发到 AI 会话。
3. 只有服务端返回完整绑定凭据、后端加密保存成功，且消息轮询成功后才显示「已连接」。扫码、已确认、网络中断和过期分别显示。
4. 保持 HomeBase 运行。可「停止接收」，已有控制任务继续，不取消、不重提；重新启动已启用通道时会恢复接收。
5. 授权失效或已停止接收时，使用「重新扫码（保留记录）」恢复同一人的授权。「解除本机绑定」会清除本通道的加密凭据和任务索引，保留已生成文件及控制任务；微信端授权由本人在手机管理。不要为重新扫码先解除绑定。

桌面显示「读取失败」时会保留最近的任务信息。刷新并核对当前绑定状态后，可以继续开始或停止接收、重新扫码或解除绑定。

二维码等待上限八分钟，过期/锁定需重新获取。当前仅本人绑定，不实现他人实名绑定或群聊。官方返回未经核实的区域服务/CDN 主机时明确停止，避免将凭据发往猜测的地址。

候选版在「停止接收」时结束微信后台对助理任务的在途查询，保留原待观察记录。恢复接收后继续查询原任务，完成通知仍按原任务返回。发送已开始而回执无法确认时，可以按原编号核对，后台沿用已有的去重保护。 暂停与恢复验收

候选版后台查询期间也能受理新要求。若新消息接管了同一轮任务的回复，旧查询返回后会再次核对归属，原任务由最新有效回复继续跟进。 [助理工作流](assistant-task-workflow.md#微信交互)

## 微信消息指令

### 回复与执行设计

| 环节 | 当前做法与保留边界 |
| --- | --- |
| 聊天与模型查询 | 问候直接回复。当前模型从配置读取。两类消息都不产生任务受理或进度通知。 |
| 排队与进度 | 由同一个任务监视器负责。只有已经受理的实际业务任务才主动发进度。列计划、查接口和模型思考期间保持安静。相同的可见进度只发一次，用户可以随时主动查询。 |
| 能力与权限 | 自然语言走 HomeBase 已注册的能力。执行器按来源、授权与工作区核对，现有文件改写和外部动作继续按能力申请确认。密钥由实际调用的后端读取。 |
| 重启与投递 | 入站去重保护业务操作，发出前的回执保护通知和附件。它们分别处理重复的微信消息和发送后回执丢失。按原任务取结果不用再运行模型或生成文件。 |
| 文件交付 | 每份文件核对原任务、路径、大小和内容摘要。旧记录兼容原投递回执，当前文件回执支持逐份核对，因此历史格式保留读取。 |
| 隔离 | 普通聊天无需文件工作区。文件访问限定授权目录，终端和第三方脚本使用执行隔离。验收用合成资料与回环微信，复用正式 worker 和本机能力，不需要另一个助理实现。 |

### 自然语言办事

日常办事可以直接说「把我刚发的视频按之前的方式剪辑」或「帮我生成一张适合做封面的图片」。助理从当前任务和相关记忆找已有偏好，再去同一份能力目录核对具体实现。偏好指向已安装的 Skill 时，先读取对应工作流和必要参数，再用已有 MCP、本机工具或 API 执行。缺少素材、描述或授权时，助理会指出具体需要补充的内容。已有记忆作为背景，当前要求和应用权限始终生效。 [助理能力与本机工具](assistant-local-tools.md)

「按之前的方式完成例会纪要」「照咱们上回那套整理纪要」也按实际事项找记忆。像「按之前的方式」这样的说法只表达沿用的意图，检索优先依据「例会纪要」等具体任务。几种现行做法在交付、费用或外发上冲突，且核对后仍无法判断时，助理会问清本次用哪种。桌面和微信共用此逻辑。

引用一条 HomeBase 原任务回复，说「再照上次的做法做一版」，助理可用已核对的原用户请求查找当前有效偏好。查找范围是引用所指会话里仍可直接读取的原请求；单说「照旧」而没有明确对象时，可补一句要做什么。明确提出新任务时按本次文字检索。 [腾讯微信插件的引用定位](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/inbound.ts) · [Anthropic 按需组织上下文](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

如果上一条交办在同一会话已完成并有登记产物，微信和桌面也可以直接说「再照上次的做法做一版」。接到消息时固定原任务，待开始时查当前有效偏好。中间聊了别的事、上一件事失败、尚未完成或开了新对话时，可明确说明要做什么，微信也可引用原回复。制作新版仍遵循对应能力的执行确认。 [LangGraph 的会话状态和长期偏好](https://docs.langchain.com/oss/python/langgraph/persistence) · [OpenAI Agents SDK 的会话续接](https://openai.github.io/openai-agents-python/sessions/)

可以连续改版。比如第二版通过「再照上次的做法做一版」完成后，再说「照旧，再做一版」，助理会用第二版作为当前对象，并沿同一会话已记录的任务关联查找最初的工作要求和当前偏好。每版都有独立的任务与产物。关联缺失时请指出要沿用的做法。设计参考了保留原执行记录的做法，HomeBase 每次新产出仍走对应能力的正常授权和确认。 [LangGraph 的分支与原始执行记录](https://docs.langchain.com/oss/python/langgraph/use-time-travel#fork)

也可以只说「再来一版」。如果上一版已完成且有登记产物，助理会把这句理解为继续当前事项。连续改版时，本次明确要求优先，再参考最近已完成版本的改动，然后用最初要求和当前偏好补齐未指定的细节。例如上一版已把封面从蓝色改成绿色，后续「再来一版」会沿用这项改动，长期出图偏好仍保留。找不到可核对的上一版时，助理会问要接着做哪一件。 [LangGraph 的会话记录与长期偏好](https://docs.langchain.com/oss/python/langgraph/persistence)

也可以同时交代本次变化，例如「照旧，这次把封面配色换成绿色」。明确的颜色、画幅、字幕样式或格式变化可以跟在沿用做法的短句后面。助理保留本次原话，用已有做法补足其余要求。这项变化作用于当前改版，其他事项继续使用已保存的长期默认。

候选版能按任务用途找到名称不同的 Skill、仓库和 MCP。例如剪辑偏好里只写了「蓝色画面剪辑」，而这个词只出现在已安装 Skill 的用途描述里，助理也能找到对应工作流并按需读取。发「帮我生成一张图」或「照上次的做法帮我画张图」时，如果记忆已经明确了风格和默认渠道，助理可沿用这些设置并准备本次生成。排队期间更新的偏好会在任务实际开始时读取。发送后也可以说「好了吗」或「把结果发给我」。 [统一能力发现](capability-discovery.md) · [助理上下文](assistant-context-and-recovery.md)

开发版会把标题用「头图」「封面图」或「插画」描述的记忆也作为出图偏好候选。「帮我生成一张图」就可以带出这些做法，采用时仍要按本次任务核对题材、画幅和当前可用的实现。

没有指定工具或保存过默认实现时，也可以直接说「帮我画一张蓝色封面」。助理按交付要求挑选能力，有合适的本机实现时优先避免不必要的外发。需要云模型时，先核对输入、已配置的默认凭据和费用信息，再准备实际调用。无法确认价格时会保留未知状态，明确只接受免费的任务会排除费用未知的候选。需要本人授权的操作仍通过原确认入口。 [工具定义与应用侧执行](https://developers.openai.com/api/docs/guides/function-calling) · [OpenClaw 的已安装 Skill 发现](https://docs.openclaw.ai/tools/skills)

当前开发版可直接用「刚才那件事做到哪了？」查看进度，或说「帮我把刚才的结果发过来」取回原产物。引用微信中的某次助理回复时，以已核对的原任务为准。单独的查询沿用原任务，也可在模型停用时查询。消息里还包含「改成绿色」等新要求时，整条消息交给助理理解。 [OpenClaw 的引用上下文与入站分流](https://docs.openclaw.ai/plugins/hooks/messages) · [腾讯微信插件的引用解析](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/inbound.ts)

「刚才那个做完了吗」或「帮我看看刚才那个做到哪一步了」也会直接核对原任务。一次查询选定对象后，重启继续查同一编号。要是原控制记录已经结束，但里面的实际业务结果还待核对，进度会说明这一点，并保留能核对的已完成步骤和原附件。 [长任务的进度与执行结果约定](https://google.aip.dev/151#errors)

也可以引用一条助理回复，说「把这张图的字幕改成绿色」。助理在当前微信绑定下定位原任务，正在执行的工作按原要求版本记录补充。已结束的任务可作为新一轮工作的依据。引用具体附件时，按已登记的文件身份核对；能否制作新版本取决于已接入的能力和授权。引用无法核对或指向多件事时，请单独引用原回复，或说清楚想处理的对象。 [边做边聊](assistant-conversation-and-matters.md#边做边聊)

想先看方案时，可以说「先聊聊剪辑方案」或「请先讨论这段视频截取的范围」。空闲和执行中都会进入只读讨论。原任务保持原进度和确认状态，后续再发具体要求即可。单独问「确认？」也属于讨论，待确认操作仍需要本人明确确认。 [边做边聊](assistant-conversation-and-matters.md#边做边聊)

看到一份待确认方案后，可以引用那条微信提示，再说「就这么办」或「按这个来」。助理按该消息中的原确认版本继续。如果方案已经办完、更换过，或微信没有提供可核对的引用，就会请你查看最新提示。独立发送「确认」沿用唯一待确认操作的规则，适合当前只有一项确认时使用。

候选版对「剪辑／剪片」和「生成图片／出图」等常用说法使用同一主题的记忆候选。「给文章配张头图」「画一张蓝色封面」也能召回出图偏好。明确提到剪辑或出图时，检索忽略「按上次的方式」等通用措辞造成的匹配，保留任务主题和具体关键词。到期记录不进入当前候选。Deep Agents 的系统文本块在发送模型请求前转换为文本，保留原顺序和内容，旧任务仍沿用原请求与检查点。 [DeepSeek 系统消息契约](https://api-docs.deepseek.com/api/create-chat-completion/) · [OpenAI Responses 输入契约](https://developers.openai.com/api/reference/resources/responses/methods/create)

候选版中，当助理选择已配置的 OpenAI 直连 GPT Image 路由生成单张 PNG 时，可以返回校验过的图片文件。调用沿用原凭据和确认流程，完成后可在微信按原任务取回附件。原响应中的 Base64 图片和服务商链接无需在聊天中展开。 [单张 PNG 产物接口](model-capability-library.md#openai-直连单张-png-产物)

发 MP4 后可以直接说「按之前的方式剪一下」或「帮我剪一下，还是按上次的做法」。当前会话最近 15 分钟内只有一条视频收件时，助理会使用这条原片。近期有多条时，会请你引用要剪的那段。近期没有可核对的原片时，这句话会交给助理继续理解，你也可以直接引用较早的原片。说「把我刚发的视频剪一下」会选当前会话最近一条视频收件。若该视频没有接收成功，会提示等待或重发。明确引用具体原片时，以引用为准。

「就照咱们上回的做法剪一下吧」也能使用唯一的近期原片。「能不能帮我把刚刚发给你的那段原片照老办法剪一下」会选择最新的原片。说「素材」而未指明是视频时，可引用原消息来确定对象。把原片提作参考、另指定电脑上的文件时，按本次明确的对象继续处理。

开发版也识别带口语停顿的「照旧，剪一下」和「按上次的方式，帮我剪一下」。当前会话只有一段近期原片时可直接接着剪，有多段时会请你指出原片。

刚连发两段 MP4 时，可以说「把倒数第二段视频照旧剪一下」。助理在当前会话最近 15 分钟的收件里从新到旧数第二条，再按当前要求和已有偏好剪辑。若指定位置的原片接收失败或归属待核对，会请你补发或引用原片。明确引用时优先核对该引用。引用后说「请参考这段视频的剪辑，帮我总结一下」，已有文字稿时会用它回答，文字稿未就绪时会提示核对原收件。 [腾讯微信插件的引用上下文](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/inbound.ts)

助理优先使用本次指定的时间范围，其次查已有偏好和 Skill。若已保存的做法指向一个安装的 Skill，助理可按安装名找到并读取说明及所需资源，再用实际能力执行。可以截取单段，也可以说「把刚发的视频第 5 秒到第 7 秒、再接第 1 秒到第 3 秒」，按你给的顺序一次拼成一个 MP4。多段支持同一条原片的 2 至 6 段，全部片段须在前 120 秒，每段至少 0.2 秒，合计请求时长最多 30 秒。范围或顺序不明确时会询问。

原片通过收件编号、会话归属和 SHA-256 绑定，剪辑不会修改原文件。旧收件如果缺少入站摘要，需重新发送原片。助理按同一任务回传附件，也可之后说「把结果发给我」。引用视频做总结或提问仍读取文字稿。 [助理剪辑工具](assistant-local-tools.md#微信原片剪辑)

可以引用本人发来的原片后说「用第 1.25 秒做三张封面，标题叫蓝色画面」，也可以说「把刚发的视频做封面」。助理用本机模板生成横版、3:4 和 9:16 三张 PNG，保留原片。原片未接收、会话归属不明或时间点超出原片时，会主动提示。 [封面工具](assistant-local-tools.md#从微信原片生成封面)

原片转写已登记时间字幕时，可以引用原片后说「把 8 到 12 秒放前面，再接 1 到 4 秒，给我一份独立字幕」。完成后同一个任务返回拼接成片和与它对齐的 SRT。桌面共享会话可预览原 SRT。 [拼接与字幕](assistant-local-tools.md#微信原片剪辑)

同一条原片也可交办「帮我做短视频发布包，沿用刚才的片段顺序和封面时间」。助理核对片段、时间、标题、简介和已登记字幕后，返回一份 ZIP，其中有竖版成片、SRT、三张封面、图文草稿与清单。保留原任务编号，供桌面同一会话打开或导出。 [发布包用法](assistant-local-tools.md#短视频发布包)

剪完后，可以直接说「只留这版成片的前两秒」。如果当前对话最新任务明确对应一份已登记成片，助理会自动用它。要修改更早的一版，可以引用那份成片或任务回复。说「这次只留原片前两秒」则按已核对的原片时间剪。两种做法都单独生成新版。

即使已经按成片时间连续剪过几版，也可以说「这次只留原片前两秒」。助理沿当前会话的剪辑任务、回执和已登记的成片摘要找到最初的原片，重启后也按原关联核对。记录缺失或摘要对不上时，会请你引用原片或最早那次剪辑的回复。执行前仍检查原片的归属和实际文件摘要。

说「只留前两秒」时，如果已经确定是哪份成片，助理会问你按原片还是按成片。追问送达后，可以紧接着回复「按成片」或「按原片」，沿用刚才的范围和素材。回复须在 15 分钟内，重启也可继续。已经问过别的事或切了会话时，可以引用要剪的视频重新说明。只说「再短一点」还需要补充时长。无法确定版本或文件发生变化时，助理会提示核对原结果。

助理附件的发送回执按原任务、文件位置摘要和内容摘要保存。同内容的不同文件分别核对。「好了吗」会同时说明任务进度和待核对的附件。若微信的文件消息回执丢失，「把结果发给我」会保留原文件并提示核对手机。确认没收到时，可以引用那条单份附件发送提示，说「这张没收到，重发一下」。只尝试发送提示对应的原文件，切到别的任务后也可用。提示缺少可引用的微信回执时，可以引用原任务回复，说「重发 result.png」。微信接口接受只表示平台响应成功。 [腾讯微信插件的引用定位](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/inbound.ts)

同一任务有多份文件时，回复会列出最多三项。可以引用这条列表说「只发第二份」，或引用文件消息说「把这份发给我」。未引用的编号按当前助理任务最近一次附件列表核对。进程重启后，已受理的请求仍使用原列表中的选择。若某份的发送回执待核对，确认手机没收到后，可以对原列表说「重发第二份」，或引用文件消息说「重发这份」。旧回执缺少引用绑定、引用冲突或文件变动时，助理会提示核对原任务。

知道文件名时，可以说「请把蓝色封面.png 发给我」。助理从当前会话的近期结果中按原文件名查找，范围最多为最近 40 条消息及当前任务，每个任务沿用最多三份附件的范围。较早的结果可引用原任务回复。若有重名，助理会请你引用对应的一份。找到后沿用原任务和附件的发送回执，进程重启后仍使用原选择。 [腾讯微信消息及附件协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)

助理回复的引用关系和逐文件发送结果会存入可跨版本写回的加密记录。回退期间，旧版按自身支持的方式回复。重新开启候选新版后，可继续识别已保存的引用和待核对的发送结果。

## 结果、失败与恢复

发送「确认」或「拒绝」后，微信继续跟进原任务。任务还在进行时会简短回应。已经完成、已拒绝或需要确认另一项操作时，直接更新原任务的结果或发出新的确认提示。重启后仍按原编号查询，保留原回复归属和去重记录。 [Google 长任务接口的进度与结果约定](https://google.aip.dev/151)

跟进和主动查询都按原轮次编号核对回复。状态缺失、无法识别、前后矛盾或编号不符时，后台保留上次核对的状态与结果，并按既有间隔重查。主动查询会提示暂时无法核对原任务。已明确停在「结果未知」的任务会显示相应说明，可继续用原编号查看。

任务先在加密微信账本记录，再以入站消息编号派生稳定 request-id，交给现有控制器或共享助理。重复消息复用原请求，不重新生成。控制器的持久任务账本与所有原有 CLI 策略保持有效。明确指令任务完成后自动回复摘要，附件在 `/结果` 时上传；共享助理在本人要求返回文件并登记交付后可自动发送，也可 `/结果` 再获取。助理重启中断不自动重放后续操作，须核对原 job。

候选版的明确指令用中文描述受理、处理中、服务商排队、业务失败、完成及结果待核对，并保留微信原任务编号。服务商返回排队或处理中时，可以按回复中的 `/模型状态` 查询原生成任务。系统和显卡结果展示常用规格与探测状态，不附带本机账号或主机名。视频生成回复给出时长和取回方法，实际文件继续经 `/结果` 核对后发送。完整控制记录可在桌面和 CLI 查询。

候选实现将已取得的助理结果先记为「待发送」。仍在同一微信授权下，重新开启接收后可从账本继续发送原文字和已登记附件。发出请求前会把送达状态保存为「回执未知」，以防微信已收到但本机没来得及保存回执；此状态不会自动补发。重新扫码会把尚未发送的旧授权完成通知标为「未发送」，原结果可通过 `/结果 原编号` 取回。

明确命令的完成摘要也支持同一授权下恢复发送。可确认还未发送的摘要沿用原发送编号；已经尝试发送且回执不明时保留原状态。收到 `/结果 原编号` 后，HomeBase 优先读取本微信账本中已经核对的控制任务结果和附件，不重新提交任务。

候选版本中，已停下的助理轮次关联多项业务任务时，「进度」或 `/状态 原编号` 会区分仍在处理和暂未查到最新状态的任务。`/结果 原编号` 仍能取回其他已经确认的附件；稍后可以再次查询同一个编号。

引用本人发出的原任务，或引用已关联原任务的助理回复、进度和附件，可直接问「好了吗？」或「结果呢？」。引用助理发送的消息需要服务端返回可核对的编号。有多个匹配、引用无法核对或未关联任务时，用 `/状态` 或 `/结果` 加原任务编号。 [腾讯 iLink 引用字段](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/types.ts#L137-L170) · [发送回执字段](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/types.ts#L219-L229)

仅可发送通道 workspace 内、非链接、非空、至多 20 MiB 的支持格式；上传前核对任务中的 SHA-256。按官方 AES-128-ECB/PKCS#7、上传参数和 CDN 下载引用封装，作为微信文件附件发送（包括 MP4）。

### 视频转写（候选）

绑定本人可以在微信单独发送 MP4 视频或 `.mp4` 文件，大小不超过 10 MiB。HomeBase 从已核验的官方 CDN 路径接收，提取第一条音轨的前 120 秒，并用已经安装的本地 CPU Whisper 生成文字稿。收到视频后可用 `/状态 原收件编号` 查询，转写完成自动返回文字稿文件，也可以通过 `/结果 原收件编号` 再取。桌面的「微信连接」页显示原收件编号和回复状态。

同一消息只登记、下载和提交一次。重启后只观察原转写回执，查不到回执时显示待核对；重新授权后可重新查询原编号。视频没有音轨、没有识别到语音、解码失败和转写未完成分别提示。微信原生视频报告密文长度，文件附件报告原文件长度。收到后验证 MP4 文件头、解密长度和随附的校验值。无需模型 API Key，本机私有目录保留原视频、派生音频和文字稿。 [腾讯 iLink 消息和附件字段](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md#messageitem)

收到公开协议未列出的结构化条目，且消息中没有可读文字或已支持的音视频与 PDF 时，回复「我读不到这条分享的内容」，并在原编号中记录状态及回复回执。仍可发送原视频转写，或用「帮我收录」保存分享链接。原始条目内容留在传输过程中，只有来源、收件编号和回复状态进入账本。若微信服务端省略了整个分享，HomeBase 收不到条目，也无法发送这条提示。目前视频号卡片解析和手机端接收复验待完成。 [腾讯 iLink 消息类型](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md#messageitem)

不写入或修改现有 SOPS/DPAPI 模型 Key、不导出 Token/配对码、不开放公网端口。微信通道内部复用本机控制器，不公开其认证端点。普通 `wechat_status` 只返回连接状态和最近任务摘要，不返回登录身份、消息正文、二维码或会话上下文。

微信账本最多 5,000 条消息，结果存储设容量上限，超限或持久化失败明确停止而不是删除去重记录。清除索引需要用户理解影响后解除本机绑定；不会自动清理用户数据。

## 协议与验证边界

### 入站消息编号兼容（候选）

外层 `message_id` 缺失时，使用首个可用的消息条目 `msg_id`。首次入站生成的收件编号保持不变，后续同一条消息同时提供两个编号时，将已核对的关联摘要保存进加密账本。重投、重启和同一账号重新授权后，已记录的编号继续指向原收件或轮次。PDF、视频和普通文字共用这条识别路径。

入站关联的摘要也存入旧版写回时会保留的请求记录。重新打开候选新版后，使用另一种已登记编号重投时仍会找到原收件。回退期间旧版使用自己的去重规则。

两个编号已经指向不同收件时，保持原记录并跳过该条消息。之前版本仅保留单个编号的旧记录，仍可用原收件编号查询。当客户端从未同时提供两种编号，也没有旧媒体引用能证明关联时，HomeBase 无法核对它们是否为同一条消息。 [腾讯 iLink 入站实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/inbound.ts#L187-L195)

### 授权失效与保留记录的重新扫码

`state=expired` 表示服务端明确返回令牌失效。该状态跨重启保留，不自动重试、重发或清空绑定。停止接收后可点击「重新扫码（保留记录）」。保存前取消、保存失败、二维码过期和不同本人扫码都不替换原账本。手机已确认且授权持久保存后，迟到取消会明确返回“已经保存”。没有进行中的扫码时，取消操作不会停止已有接收。

候选实现允许在微信授权失效时，带着已受理的助理轮次和控制器任务，以及当前来源已提交的本机音视频转写重新扫码。后台继续观察原轮次、原控制任务或原收件；旧回复上下文停用。原记录继续更新，新消息可用 `/状态 原编号` 或 `/结果 原编号` 查询文字和已登记附件。手动暂停和尚待核对是否受理的记录仍遵循原预检。

成功只更新同一本人的连接授权，原任务编号、未知投递回执、通知去重及助理逻辑渠道身份保持；机器人编号变化也不自动开启一套新助理上下文。旧回复上下文不当作新授权可用的证据，首次收到新本人消息后再恢复主动通知。PIN、二维码和令牌不进入接口说明或诊断输出；实际手机扫码及connected仍须另验。明确「解除本机绑定」仍是清空本机微信索引的操作，不属于重新授权流程。

未构建和切换的源代码不代表当前运行程序已支持此入口。

基于 [腾讯官方协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md) 的本人扫码/PIN 合同，通报 `3.0.0/homebase-0.1.0` 和 `HomeBase/0.1.0`，不是安装 OpenClaw 或宣称第三方客户端身份。官方协议本身不保证所有账号、地域和未来版本行为；真实账号连接须现场验收。
